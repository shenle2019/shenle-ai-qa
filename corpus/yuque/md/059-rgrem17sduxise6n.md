## **2.****项目经历描述：**

读书屋项目系统是一套基于 Spring Boot 3 + Vue 3 开发的前后端分离型小说项目，由小说门户系统、作家后台管理系统、平台后台管理系统等多个子系统构成。市场上类似的产品有：7猫小说、番茄小说等。读书屋免费小说是一款提供小说阅读服务的系统。小说内容覆盖了言情小说、穿越架空小说等各种类型。系统功能包含：小说阅读、搜索、小说评论、书架管理、作者管理、小说编辑、收费系统、作者邀请机制等功能特性。

​

**系统架构说明：**

系统基于JAVA语言，采用了分布式技术架构。支持多终端应用，包含3大子项目：读书屋小说后端运营管理系统、读书屋小说PC网站、读移动APP应用

​

● 提前整理项目需求，以便在评审会上积极发言，提出疑问及建设性建议。

**自动化测试**

#### **3.6.****这个过程中你印象最深刻的BUG有哪些？**

在测试书架管理功能时，发现用户在手机上添加或删除书籍后，书架状态不能实时同步。这导致用户在不同设备上看到不一致的书架列表。随后通过日志分析和用户行为模拟，定位到问题出在后端数据库与前端Vuex状态管理的数据同步机制上。随后，我们优化了后端API的响应速度和前端的状态更新逻辑，并引入了WebSocket技术来实现实时数据同步。经过多轮测试验证，最终解决了书架同步异常的问题。这次经历让我更加理解了前后端协作的重要性，以及如何在复杂系统中排查和解决同步问题。

说明哪个流程复杂；

复杂的原因是什么，从哪体现出复杂，是技术栈多样还是业务场景复杂还是团队协作有问题；

​

我认为最复杂的莫过于“小说阅读功能的端到端测试”。这一流程之所以复杂，主要体现在以下几个方面：

1. **功能复杂度高**：小说阅读功能不仅涉及到前端Vue 3组件的渲染和交互，还需要与后端Spring Boot 3服务进行大量的数据交互，包括小说内容的获取、章节的切换、阅读进度的保存等。这些功能的协同工作使得测试流程变得复杂。

2. **用户体验要求高**：作为用户最直接接触到的功能之一，小说阅读功能的用户体验至关重要。我们需要确保在各种设备、网络环境下，用户都能流畅地阅读小说，包括页面加载速度、阅读界面的布局、字体大小和颜色等细节都需要经过严格测试。

3. **异常处理机制复杂**：在阅读过程中，用户可能会遇到各种异常情况，如网络中断、服务器错误、小说内容格式问题等。我们需要确保系统能够妥善处理这些异常，给出明确的提示信息，并尽可能恢复用户的阅读进度。

4. **多平台兼容性测试**：由于读书屋项目系统支持多种设备和操作系统，我们需要在不同平台上进行兼容性测试，确保小说阅读功能在不同环境下都能正常工作。

5. **与其他功能的联动测试**：小说阅读功能还与其他功能紧密相关，如书架管理、搜索、评论等。我们需要确保这些功能之间的联动性，例如从搜索结果中直接进入阅读页面、在阅读页面添加评论等。

为了应对这些复杂性，我们采用了以下策略进行测试：

● **编写详细的测试用例**：针对小说阅读功能的每个功能点，我们编写了详细的测试用例，包括正常流程、异常流程和边界条件等。

● **使用自动化测试工具**：我们引入了自动化测试工具，如Selenium、Cypress等，对小说阅读功能进行端到端的自动化测试，提高测试效率和准确性。

● **进行多轮迭代测试**：在开发过程中，我们进行了多轮迭代测试，不断发现和修复问题，确保小说阅读功能的稳定性和可靠性。

**测试案例名称**：前后端分离架构下的小说搜索功能测试

**测试背景**：

读书屋项目系统采用了前后端分离的架构，前端使用Vue 3进行开发，后端使用Spring Boot 3进行开发。其中，小说搜索功能是系统的一个核心功能，用户可以通过前端页面输入关键词进行搜索，并获取到相关的小说列表。

**测试难点**：

1. **接口测试**：需要确保前端页面与后端API的交互顺畅，数据传递正确。这要求测试人员不仅要熟悉前端的测试，还要熟悉后端的测试，以及前后端之间的接口测试。

2. **功能正确性**：需要测试小说搜索功能的正确性，包括搜索结果的准确性、搜索结果的排序方式、搜索结果的分页显示等。

3. **性能测试**：需要测试在高并发情况下，小说搜索功能的响应时间和吞吐量是否满足要求。

经过测试，我们发现小说搜索功能在前后端分离架构下能够正常工作，搜索结果准确，排序方式和分页显示也符合需求。同时，在高并发情况下，小说搜索功能的响应时间和吞吐量也满足要求。但是，我们也发现了一些潜在的问题和缺陷，如搜索结果的缓存机制需要优化、搜索结果的展示方式需要改进等。这些问题和缺陷已经与开发团队进行了沟通和确认，并进行了修复和回归测试。

3. **优化服务器性能**：如果接口调用超时是由于服务器负载过高或响应时间过长导致的，将优化服务器性能。

#### **3.12 用户如何提交小说评论？评论在提交后是否需要经过审核？审核流程是怎样的？**

**用户如何提交小说评论**

在读书屋系统中，用户提交小说评论通常是通过以下步骤完成的：

1. **进入小说详情页**：用户首先需要在系统中找到并点击进入想要评论的小说的详情页。

2. **找到评论区域**：在小说详情页中，用户可以看到一个专门的评论区域，这个区域通常位于页面的下方或侧边栏。

3. **填写评论内容**：用户需要在评论框中填写自己的评论内容，这可能包括对小说的评价、对角色的看法、对剧情的猜测等。

4. **提交评论**：填写完评论内容后，用户点击提交按钮，系统就会将评论发送到后台进行处理。

**评论是否需要经过审核**

是的，在读书屋系统中，用户提交的评论在显示给其他用户之前，需要经过一定的审核流程。

**审核流程是怎样的**

读书屋系统的评论审核流程

1. **自动审核**：系统首先会对用户提交的评论进行自动审核。这一步骤通常是通过设置敏感词过滤、检测评论内容是否包含违规信息等方式来完成的。如果评论内容被系统判定为违规，那么这条评论就会被自动拦截，不会显示给其他用户。

2. **人工审核**：对于自动审核无法确定是否违规的评论，或者系统认为可能存在争议的评论，系统会将其送到人工审核环节。人工审核通常是由系统管理员或专门的审核团队来完成的。他们会仔细阅读评论内容，并根据系统的规定和审核标准来判断这条评论是否应该被通过。

3. **审核结果通知**：无论评论是通过自动审核还是人工审核，系统都会在审核完成后给用户发送一个通知，告知他们评论的审核结果。如果评论被通过，那么它就会显示在小说的评论区域中，供其他用户查看和回复。如果评论被驳回，那么系统通常会给出驳回的原因，并允许用户修改后重新提交。
