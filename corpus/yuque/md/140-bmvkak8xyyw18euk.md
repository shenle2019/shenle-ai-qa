# 概述

## 简介

## 场景举例

**用银行取钱场景类比性能测试概念**

### 性能测试类型

|  |  |  |
| --- | --- | --- |
| **测试类型** | **银行场景类比** | **性能测试说明** |
| **负载测试** | 假设银行有 **3个窗口**，测试 **100个客户** 在 **30分钟** 内能否全部完成取钱。 | 验证系统在预期负载下是否满足性能要求（如响应时间 ≤2分钟，无错误）。 |
| **压力测试** | 让 **200个客户** 同时涌入银行，观察窗口能否承受（是否崩溃或响应极慢）。 | 测试系统在超负荷下的表现，找出崩溃点或性能瓶颈（如最大支持并发客户数）。 |
| **稳定性测试** | 银行连续 **24小时营业**，每半小时来 **50个客户**，观察窗口是否始终正常。 | 验证系统在长时间运行下的稳定性（如内存泄漏、资源耗尽风险）。 |

### 2. 核心性能指标

|  |  |  |
| --- | --- | --- |
| **指标** | **银行场景** | **性能测试对应** |
| **TPS** | 窗口每秒处理的客户数（如 **1个窗口每分钟处理3人 → TPS=0.05**）。 | 每秒完成的事务数（Transactions Per Second），衡量系统吞吐量。 |
| **响应时间** | 客户从排队到取钱完成的总耗时（如平均 **2分钟**，最长 **5分钟**）。 | 请求从发送到收到响应的时间，关注平均值、90%分位值。 |
| **错误率** | 因ATM故障、密码错误导致取钱失败的客户比例（如 **100次操作中失败2次 → 错误率2%**）。 | 失败请求占比，通常要求 ≤1%。 |
| **资源利用率** | 银行CPU（员工效率）、内存（排队区容量）、网络（交易系统带宽）的使用率。 | 服务器CPU、内存、磁盘I/O、网络带宽的占用情况，通常要求 ≤70%~80%。 |

### 3. 测试场景设计

##### **场景1：常规负载测试**

- **银行配置**：3个窗口，每个窗口处理速度 **2分钟/人**。
- **测试目标**：5分钟内处理 **50个客户**。
- **JMeter参数**：

- **线程数（客户数）**：50
- **循环次数**：1（每个客户取钱一次）
- **Ramp-Up时间**：5分钟（客户逐步到达）

##### **场景2：高并发压力测试**

- **银行配置**：3个窗口，但突然涌入 **100个客户**。
- **观察现象**：

- **窗口响应时间**：从2分钟延长到10分钟。
- **排队队列溢出**：客户因等待超时离开（错误率上升）。
- **员工CPU过载**：因疲劳导致处理速度下降。

- **JMeter参数**：

- **线程数**：100
- **Ramp-Up时间**：0秒（瞬间到达）

### 4. 性能瓶颈分析

|  |  |  |
| --- | --- | --- |
| **瓶颈类型** | **银行表现** | **性能测试对应问题** |
| **硬件资源不足** | ATM机现金不足或CPU过热死机。 | 服务器内存不足、磁盘IO瓶颈。 |
| **软件配置问题** | 窗口系统卡顿（如升级后软件变慢）。 | 数据库连接池过小、线程池配置不合理。 |
| **代码效率低** | 员工操作流程繁琐（如手动填写单据耗时）。 | 程序算法复杂度高、未使用缓存。 |
| **网络延迟** | 银行与总行系统通信延迟，导致身份验证慢。 | API调用超时、数据库查询延迟。 |

### 5. 优化方案

|  |  |  |
| --- | --- | --- |
| **优化方向** | **银行改进措施** | **性能测试优化方法** |
| **横向扩展** | 增加窗口数量或部署更多ATM机。 | 增加服务器节点，使用负载均衡（如Nginx）。 |
| **纵向升级** | 培训员工提升效率（如从2分钟/人 → 1分钟/人）。 | 升级服务器硬件（CPU、内存）。 |
| **流程简化** | 客户自助填单机减少人工操作。 | 优化代码逻辑，减少数据库查询次数。 |
| **异步处理** | 非紧急业务（如打印流水）延后处理。 | 使用消息队列（如Kafka）异步处理非核心任务。 |

### 6. 测试报告关键内容

### **总结**

通过银行取钱场景，可以直观理解性能测试的核心概念：

1. **负载与压力的区别**：正常排队 vs 挤兑事件。
2. **性能指标的意义**：TPS反映效率，响应时间影响体验，错误率暴露系统缺陷。
3. **优化方向**：扩展资源、简化流程、异步处理。

实际性能测试中，需像管理银行一样精细化设计场景、监控资源、分析瓶颈，才能确保系统在高并发下稳定运行。
