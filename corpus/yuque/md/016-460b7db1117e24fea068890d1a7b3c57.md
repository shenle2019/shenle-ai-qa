# 测试工作流程与测试计划

- 测试工作流程`重要`

- 软件需求的评审`重要`

- 测试计划的编写`重要`

> 通过本节课需要知道： 必须知道测试工作的整体的流程，这个和我们的岗位息息相关。所以一定是滚瓜烂熟的。

## 一、测试工作流程

> 通过软件的生命周期的学习及它对应的开发测试模型，大家都应该清楚软件测试是个复杂的过程，其涉及着大量的人员安排、资源准备、工作活动分配、工作活动实施、工作进度监控等。稍有疏漏就会影响测试工作的开展，进而影响到整个项目进度和产品质量的检测。那真正规范的测试流程到底是怎样的呢？

规范的软件测试流程阶段划分：

- 需求评审阶段

- 测试计划阶段

- 测试设计阶段

- 测试执行阶段

- 测试评估阶段

## 二、需求评审阶段

> 首先做任何事情之前，必须要需求评审。评审软件需求，提出需求中存在的问题或建议

参考文档：软件需求规格说明书

**任务： 评审软件需求**

### 2.1 什么是软件需求？

> 需求是产品必须完成的事以及必须具备的品质。需求包括：功能性需求、非功能性需求和限制条件。

**功能性需求**：功能性需求是产品必须完成的那些事，要求一定的功能和品质。

例子：微信可以给好友发消息、发红包、 发语音和视频等操作

**非功能性需求**：非功能性需求是产品必须具备的属性或品质。诸如观感、可用性、安全性和法律限制等。

例子：x 平台用户数为5万人，每天登录用户数为1万左右，网络的带宽为100M带宽。在工作时间根据资料名称条件进行搜索，可以在3秒内得到搜索结果。

2021年天猫活动的订单处理峰值达高于58.3万笔/秒，要求订单成功率为100%

> 注意：在项目中一般优先分析功能性需求（满足需求），产品的功能确定之后再分析非功能性需求。

**限制条件**：在需求分析中需要考虑一些条件约束，规则等，比如客户的约束，行业的约束，法律的约束以及自己的约束。

例如：客户需求：x平台必须在2021年开学的第一学期上线

### 2.2 需求评审步骤

### 2.3 为什么要需求评审

- 确认需求完整与准确

- 理解一致

- 降低因为需求不明确带来的项目失败的风险

### 2.4 测试主要职责

- 确认自己理解需求、无疑义

- 确认需求无明显错误、能够支撑后续的用例设计等

- 提出一些改进建议

## 三、测试计划编写

> 主要任务是编写测试计划，测试计划是一个叙述了预定的测试活动的范围、途径、资源及进度安排的文档（word 、excel）。它确认了测试项（测试范围）、被测特征、测试任务、谁执行任务、各种可能的风险。

参考文档：软件需求规格说明书、项目总体计划、项目开发进度表

**任务： 编写测试计划**

### 3.1 **为什么要编写测试计划？**

- 测试计划可以有效预防计划的风险，保障计划的顺利实施

- 了解项目和测试活动的整体情况，有利于对项目和测试活动进行宏观调控

- 明确职责分工，便于沟通和协作

- 明确测试活动的对象、范围、方法、进度和预期结果等资源统筹配置

- 明确自身和团队的测试任务以及测试成功的标准、要实现的目标

- 风险管控和消除可能存在的风险，降低由不可能消除的风险所带来的损失

### 3.2 **编写测试计划步骤**

- 任务到达  
  测试负责人接到软件测试任务书和被测软件的需求说明，开发的进度表

- 分析测试任务  
  充分理解被测试软件的需求，评估被测软件的进度、状态、复杂度和潜在风险

- 资源规划和配置  
  组建测试团队，准备各种非人力资源

- 制定测试计划  
  研究确定测试计划的各项内容

- 评审测试计划  
  测试团队共同参与评审测试计划

### 3.3 测试计划核心内容

- 明确测试目标，确定测试范围

- 确定总体的测试方法（测试策略）

- 确定测试资源：测试什么？由什么谁来执行？如何测试？

- 确定测试周期：为测试的设计、实施和评估安排时间进度

- 进行风险评估

### 3.4 编写测试计划方法

> 可以使用5W1H 的方法去进行编写测试计划

|  |  |
| --- | --- |
| WHAT —对象 | WHY—原因 |
| 测试什么？ 做什么类型的测试？ 被测软件的特点是什么？ 在什么环境下测试？ | 为什么要做性能测试？ 为什么重点测试这个部分？ |
| **WHO—参与人** | **WHEN—时间** |
| 软件的最终用户是谁？ 谁来设计测试用例？ 谁来执行测试用例？ | 什么时候开始测试？ 什么时候提交缺陷报告？ 什么时候结束测试？ |
| WHERE—场所/环境 | HOW—方式 |
| 在哪里进行测试？ 测试软件的哪个版本？ 测试到哪里算是完成？ | 如何进行测试？ 如何管控风险？ 如何控制项目进度？ |

### 3.5 测试计划和测试方案的区别

- 测试计划

- 概念：是指描述了要进行的测试活动的范围、方法、资源和进度的文档。

- 核心内容：

- 范围与目标

- 角色与职责

- 进度与资源

- 风险与应对

- 准入准出标准

- 测试方案

- 概念：是从测试的技术角度去分析需求，在方向上明确要怎么测，分析结果重点在于测试策略与技术实现。

- 核心内容

- 方法

- 环境

- 工具

- 测试计划是【管理型】文档，测试方案是【技术性】文档

- 测试计划主要解决【做什么？】【谁来做？】，测试方案主要解决【怎么做？】

- 主要内容存在差异：

- 测试计划主要内容如下：

- 目标与范围

- 角色与职责

- 资源与进度

- 风险与应对

- 准入与准出

- 测试方案主要内容如下：

- 策略与方法

- 环境

- 工具的选择

> 主要任务是搭建测试环境、执行测试用例和提交缺陷报告的工作

参考文档：测试环境搭建指导文档、测试用例、缺陷规范

**任务1：搭建测试环境**

**任务2： 执行测试用例**
