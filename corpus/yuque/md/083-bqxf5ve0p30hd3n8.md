**识别磁盘瓶颈**：

- **高 I/O 使用**: 关注 `DISK READ` 和 `DISK WRITE` 列的高数值，这些代表大量的磁盘读写操作。

常见开发bug：insert into 表名 ： 数据插入操作

- **高 I/O 等待**: 如果某些进程的 `IO` 列显示高百分比，说明这些进程正在等待 I/O 操作完成，可能表明磁盘 I/O 成为系统瓶颈。
- **进程名称**: 注意那些高 I/O 使用率的进程名称（`COMMAND` 列），这些进程可能是导致磁盘瓶颈的主要原因。如果有不必要的进程，我们可以尝试关闭

**采取措施**：

- **优化问题进程**: 如果某个进程的 I/O 使用率过高，检查该进程是否可以优化，比如减少不必要的磁盘操作或调整其配置。
- **硬件升级**: 如果整体 I/O 使用率很高且无法通过软件优化解决，考虑升级硬件，如使用更快的 SSD 替代 HDD 或增加磁盘带宽。

当然，文件上传是一个简单的用例，实际上，我们在日常工作中，会有很多的操作，而但凡涉及到IO操作，磁盘都有可能成为我们的瓶颈问题所在，所以，在这个过程中，我们希望同学们能够举一反三的解决这些问题。

## 磁盘分区对齐fdisk

- 什么是磁盘分区对齐？

- 性能较低，原因是未对齐的分区导致每次读写操作跨越多个磁盘块，增加了I/O操作次数和延迟。
- 当我们在谈论计算机存储时，数据是以磁盘块的形式存储的。一个磁盘块通常是一个固定大小的数据单位，比如4KB。当我们对磁盘进行分区时，分区的大小应该是磁盘块大小的整数倍，这被称为对齐。
- 如果分区的大小不是磁盘块大小的整数倍，那么分区就会“未对齐”。未对齐的分区会导致每次读写操作跨越多个磁盘块。想象一下，如果你有一个8KB的数据，而你的分区只有4KB，那么你每次读写操作就会跨越两个磁盘块。
- 这会导致性能问题，因为操作系统和磁盘驱动器需要花费额外的时间来处理跨磁盘块的读写操作。这会增加延迟，降低性能。

- 如何检查对齐情况？

- 命令：`fdisk` 、
- `fdisk`是一个常用的磁盘分区工具，可以使用它来查看分区的起始扇区并计算对齐情况。
- `sudo fdisk -l /dev/sda`
- **查看起始扇区**： 在输出中查找分区的起始扇区（Start）列。确保每个分区的起始扇区是 2048 的倍数，因为这通常表示分区是 1MiB 对齐的

- 如果未对齐我们应当如何处理？

- **备份数据**
- **必须优先备份分区数据**！重新分区会导致数据丢失。
- 使用 `parted` 或 `gdisk` 创建新分区，手动指定对齐的起始位置：

**格式化并恢复数据**

- 格式化新分区后，从备份中恢复数据。

# 问题定位：如何快速定位发现内存与CPU问题？

​

### 内存（RAM）的工作原理：

1. **存储单元**：内存由一系列存储单元组成，每个单元都有唯一的地址。这些存储单元用于临时存储运行中的应用程序和数据。
2. **数据读写**：当计算机运行程序时，CPU会从硬盘等永久存储设备中读取数据到内存中。CPU可以直接访问内存中的数据，进行读写操作。
3. **随机访问**：与硬盘等存储设备不同，内存支持随机访问，这意味着CPU可以直接访问内存中的任何位置，而不需要按顺序读取。
4. **易失性**：RAM是易失性存储介质，即当电源关闭时，其中的数据会丢失。因此，它不适合长期存储数据。
5. **速度**：内存的速度非常快，远高于硬盘等存储设备，这有助于提高CPU处理数据的效率。

### CPU的工作原理：

1. **核心组件**：CPU主要由运算器、控制器、寄存器和缓存等组成。运算器负责执行算术和逻辑运算，控制器负责指挥其他硬件组件，寄存器用于临时存储数据和指令，缓存则用于提高数据访问速度。
2. **多核处理器**：现代CPU通常具有多个核心，可以同时执行多个任务，提高处理效率。
3. **指令集**：CPU可以理解和执行的指令集合称为指令集。不同的CPU架构有不同的指令集。

### 内存与CPU的协同工作：

- **数据传输**：CPU需要数据时，会从内存中读取数据到寄存器或缓存中，处理完毕后再将结果写回内存或发送到其他硬件设备。
- **指令执行**：CPU从内存中读取指令，解码并执行这些指令。
- **性能瓶颈**：CPU的速度通常远高于内存，因此内存的性能（如速度、容量）往往成为整个系统性能的瓶颈。

程序运行的时候，就是在内存中，把代码搬运到CPU中，而一个请求，就会产生一个线程，每个线程都会把代码搬运过去。如果空间不足或者运行内容被占满，就会造成性能问题。

### 内存/CPU的性能瓶颈查找命令

业界不成文规定：一个健康的系统，基本上要有个这个规则： CPU <=80% 内存 <=80% 注意：如果太低，浪费服务器资源 ，如果太高，随时都有死机的风险。

​

CPU与内存在日常的测试过程中，是非常敏感的，任何其他组件造成的瓶颈最终都会体现在CPU与内存上，比如内存与CPU的升高，那么我们应该如何去定位瓶颈所在呢？

`top命令` 内存与CPU整体查看的命令:

​

展示内容如上图:

|  |  |
| --- | --- |
| 行数 | 实际意义 |
| 第一行:系统运行信息 | 当前时间,系统运行了多久,登录用户有多少,系统负载信息 |
| 第二行 任务信息 | 总共多少进程，正在运行的几个，休眠梳理，停止，假死 |
| 第三行 CPU信息 | 这里是表示cpu的占比数，详情看下方 |
| 第四行 内存的使用信息 | 总量，空闲大小，已经使用的大小，用于缓存的大小 |
| 第五行 虚拟内存/交换内存 | 这玩意 本质 是在 硬盘上面开辟一块空间当成 内存来用 |

- 第一行的 **load average：**

- 0.00, 0.01, 0.05 系统平均负载（过去 1 分钟、5 分钟、15 分钟的平均值）。
- 计算方式：每5秒检查一次活跃进程数，然后用这个数值 ，除以CPU核数。
- 系统小判定：活跃进程数/CPU >5 ,就表示系统**超负荷运转**
- 说明：进程 一般表示软件 ，线程是软件运行时自动产生的最小单位.

- 第三行 CPU（s）

- us 表示用户CPU占用比例
- sy 表示系统CPU占用比例
- ni 表示改变过优先级的进程CPU占比
- id 表示空闲CPU占比
- wa 因为I/O等待造成CPU占用
- hi 表示硬中断CPU占比（强制停止运行）
- si 表示软中断CPU占比
- st 表示等待虚拟机调度，只有虚拟机有，物理机一般都是0

​

以上就是我们的top命令，top命令能帮助我们快速定位问题，比如：我们在性能测试的时候，有可能会碰到cpu 内存上升到99%的情况，但是这个时候我们要注意，我们不一定能百分之百保证，这都是我们当前程序引起的问题。

所以我们可以去检查对应的进程 ，输入top命令，来进行监控和诊断：

- 假设 我们看到一个输出

PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND

12345 user1 20 0 279016 31476 15896 R 70 0.4 0:12.85 其他

12345 user1 20 0 279016 31476 15896 R 29 0.4 0:12.85 项目

**分析**:这时候，我们可以看到 这个其他，占用了cpu的 70% ,而实际的项目 占用的只有29，这时候我们就可以知道，这个进程占用了大量的计算，或者卡在了某个循环中.

而内存使用率 只有百分之 0.8， 这就表示内存不是问题所在。

这里我们要注意，如果一旦,系统的整体CPU使用率显示用户空间（us）使用了25.9%，系统空间（sy）使用了3.0%，而空闲（id）为71.1%，这表明系统还有空闲的CPU资源。

这个例子，我们可以看到top命令在性能中的实用性，可以快速帮我们定位到可能引起性能问题的进程.

难点说明： 使用`top`命令监控Linux系统时，可能会遇到一个进程显示其CPU使用率为99%，而同一时间`top`命令显示的总体CPU使用率（`%Cpu(s)`）却只有25%,这是为什么？

在多核心系统中，一个进程可能只在一个或几个核心上运行，而不会使用所有核心。因此，即使某个进程在其运行的核心上达到了99%的使用率，其他核心可能仍然处于空闲或低负载状态。

## 【了解】java程序的编译与运行流程

java程序 可以通过javac 命令，将.java文件编译成 .class文件，这个步骤是必须的，java 的代码必须要再jvm内部才能运行。所以，一个java程序加载运行的流程如下:

jvm环境会先从内存中 划分一部分给自己，表示这部分内存被自己使用了。然后开始运行其他内容:

​

类加载器(Class Loader) : 负责将编译好的.class字节码文件加载到内存中，使得JVM可以实例化或以其他方式使用加载后的类。

​

类加载器支持在运行时的动态加载，动态加载可以节省内存空间，灵活地从本地或者网络上加载类

​

方法区/元数据区 ：

​

方法区也就是我们常说的永久代区域，里面存储着Java类信息、常量池、静态变量等数据，方法区占用的内存区域在JVM中是线程共享的

​

在JDK1.8及以后的版本中，方法区已经被移除，取而代之的是元数据区和本地内存，类的元数据信息直接存放到JVM管理的本地内存中。需要注意的是，本地内存不是虚拟机运行时数据区的一部分，也不是Java虚拟机规范中定义的内存区域。常量池、静态变量等数据则存放到了Java堆（Heap）中。

​

Java虚拟机栈 & 本地方法栈 & 程序计数器 ：线程私有的，和线程运行代码直接相关

​

堆区：Java是一门面向对象的程序设计语言，而JVM堆区是真正存储Java对象实例的内存区域。堆的大小不等于JVM可同时存储这么多数据

​

特别注意: 堆的内存，性能问题很多都是由此而生的。

​

因为堆内存中，要做垃圾回收，简单理解：搞卫生， 搞卫生的过程就是把家里的东西要移动开，打扫才行，如果家里堆满了，那就根本没法移动任何东西

## 数据库的事务机制详解

​

事务机制ACID : ACID 模型是一组数据库设计原则，对于事务型应用程序非常重要。

​

\* Atomicity 原子性 : 事务通常由多个语句组成。原子性保证将每个事务视为一个“单元”，该事务要么完全成功，要么完全失败

\* Consistency 一致性： 事务的执行不能破坏数据库数据的完整性和一致性，一个事务在执行之前和执行之后，数据库都必须处于一致性状态

\* Isolation 隔离性： 通常数据库会有多个事务同时执行，隔离可确保事务的并发执行不会相互干扰。

\* Durability 持久性 ： 持久性保证一旦事务被提交，即使在系统故障（例如，停电或崩溃）的情况下，事务也将保持提交状态

​

这个过程中，我们可以执行一个 或者 多个SQL的执行， 我们可以明确它的开始和结束.

## 数据库锁机制

数据库的锁机制.

我们可以开启两个linux的操作客户端，模拟一下多人向数据库写入数据的情况:

用户1： 正在操作，要删除整张表数据

用户2：正在操作，要向数据库插入数据

这个时候，我们会发现，如果用户2先开启的事务，那么当用户1执行的时候，它会被锁住，在用户2提交前，无法正常执行SQL。 这就是Mysql的锁机制。

注意：锁是一个虚拟概念，它为了满足数据的一致性，只会允许一个人去操作。这种就如同把门锁住，不让人进来这样的。大家要注意好这个要点

上述这种情况，就是我们的表锁。

​

锁很明显会出现性能问题，也就意味着，我们需要在测试过程中重点关注这个操作。
