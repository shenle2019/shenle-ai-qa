> **AI 课程简介**：AI扫盲课旨在帮助零基础小白快速掌握AI编程工具的使用。通过系统学习，你将能够熟练运用各类AI辅助编程工具，从IDE到命令行，从个人助理到综合实战，构建完整的AI编程能力体系。本课程以国产AI工具为主线，兼顾全球主流方案，助你找到最适合自己的工具组合。

# 第一模块：认知篇

> **学习目标**：不急着装工具，先把基本概念弄明白，后面学起来才不懵

## 先搞清楚：这些AI编程工具到底能干什么？

### 你说话，它写代码

想象一下，你有个程序员朋友，24小时待命，你说一句他就能帮你把代码写好。AI编程工具就是这样的存在。

比如你想做个待办事项网页，传统做法是你得自己写HTML、CSS、JavaScript。但有了AI工具，你只需要说：

> "帮我做一个待办事项网页，能添加、删除、标记完成，数据要能保存"

然后——啪——代码就出来了。

### AI编程工具能做的事

**1. 写代码**

这是最核心的能力。你描述需求，AI帮你生成代码。

举个例子："帮我写一个Python脚本，实现一个简单的登录注册功能的Flask接口"

**2. 改Bug**

程序报错是常有的事，传统做法是看报错信息、查百度、一行行调试。AI时代，你可以直接把报错信息丢给它：

> "程序报错了：[粘贴报错信息]，帮我看看哪里出了问题"

AI会分析报错原因，定位到具体哪一行代码有问题，甚至帮你改好。

**3. 加功能**

在已有代码基础上增加新功能，也很简单。比如你有个博客网站，想加上评论功能：

> "帮我给这个博客加上评论功能，用户可以留言，留言要审核后才能显示"

**4. 解释代码**

看不懂别人的代码？交给AI。它可以逐行解释代码逻辑，甚至帮你画出流程图。

> "帮我解释一下这段代码是做什么的"

### 三个能力层次

AI编程工具的能力可以分为三个层次，就像打游戏升级一样：

|  |  |  |
| --- | --- | --- |
| 层次 | 能做什么 | 打个比方 |
| **基础层** | 写代码、改Bug、加功能 | 你说它写，它就是个高级打字机 |
| **中级层** | 管理文件、执行命令 | 它不仅能写代码，还能帮你操作电脑 |
| **高级层** | 调用外部工具、自动化工作流 | 它能操作数据库、运行浏览器测试，像个全能助理 |

**为什么重要？**

了解这三个层次，你就能知道自己现在在哪一级、未来可以往哪走。

- 刚入门时，你主要用基础层功能——让AI帮你写代码

- 熟悉之后，可以尝试中级层——让AI帮你管理项目文件

- 想更高效，就需要高级层——配置MCP，让AI连接数据库、浏览器等工具

## 核心概念速通

### 大模型：工具的"大脑"

**是什么？**

大模型，全称`Large Language Model（LLM）`，是AI编程工具的"大脑"。它负责理解你说的话、生成你需要的内容。

类比一下：大模型就像不同品牌的发动机。都是发动机，能力有高有低，有的省油、有的马力大。不同的大模型，代码能力也不同。

**为什么重要？**

选AI编程工具，很大程度上是选大模型。大模型选对了，工具用起来才顺手。

**主流大模型有哪些？（国产优先推荐）**

近年来国产大模型发展迅猛，很多已经达到甚至超越国际一线水平。以下是国内主流AI编程场景常用的大模型：

|  |  |  |  |
| --- | --- | --- | --- |
| 模型 | 开发商 | 特点 | 适合场景 |
| **DeepSeek** | 深度求索 | 推理能力极强，性价比极高，开源可自部署 | 日常编程、复杂推理、深度思考 |
| **通义千问（Qwen系列）** | 阿里云 | 中文理解最好，有多版本可选 | 中文项目、全场景通用 |
| **豆包（Doubao）** | 字节跳动 | 与Trae深度集成，免费额度多 | Trae用户首选 |
| **GLM-4** | 智谱AI | 中文理解优秀，长文本处理强 | 中文场景、长文档分析 |
| **MiniMax** | MiniMax | 多模态能力强 | 创意写作、多模态 |

| **GPT-4o** | OpenAI | 全能型，生态成熟 | 日常使用、多场景 |

> 💡 **小贴士**：新手推荐从 DeepSeek 或通义千问开始。DeepSeek 性价比极高，通义千问中文理解优秀。免费额度也相对充裕。

### Token：AI的"计费单位"

**是什么？**

Token是大模型处理文字的最小单位。你可以理解为"按字数计费"——用的Token越多，花的钱越多。

怎么计算呢？大约来说：

- 1个汉字 ≈ 1-2个Token

- 1个英文单词 ≈ 1-2个Token

- 代码的Token计算比较复杂，通常比普通文字多一些

**为什么重要？**

因为这直接关系到你的花费。不同模型的Token单价差异很大，国产模型的一大优势就是**价格实惠**。

举个例子（国产模型价格明显更友好）：

| 模型 | 输入价格（每百万Token） | 输出价格（每百万Token） |
| **DeepSeek-V3** | ¥1 | ¥2 |
| **DeepSeek-R1** | ¥4 | ¥16 |

**怎么省Token？**

1. **对话不要太长**：聊了几十轮之后，AI需要记住的上下文越来越多，消耗会显著增加。适时开新对话。

1. **不要一股脑把整个大文件丢给AI**：分段处理，只丢相关部分。

1. **精准描述需求**：需求说清楚，避免来回修改。

1. **学会开新对话**：聊到一定程度，感觉AI开始"健忘"或者反应变慢，开个新对话重新开始。

> 💡 **小贴士**：大多数工具都有Token消耗提示，看到消耗太高就换个方式问，或者开新对话。

### API Key：大模型的"门禁卡"

**是什么？**

API Key是一串字符，可以理解为调用大模型的"门禁卡"。有了它，AI编程工具才能连接到云端的大模型来工作。

**怎么获取？**

你需要到大模型提供商的官网注册账号，然后创建一个API Key。常见的中文提供商：

|  |  |  |
| --- | --- | --- |
| 提供商 | 官网 | 支持的模型 |
| **DeepSeek** | platform.deepseek.com | DeepSeek V3 / R1 |
| **阿里云（通义千问）** | dashscope.console.aliyun.com | Qwen全系列 |
| **智谱AI** | open.bigmodel.cn | GLM-4全系列 |
| **火山引擎（豆包）** | console.volcengine.com | 豆包系列 |

| **零一万物** | platform.lingyiwanwu.com | Yi系列 |

| OpenAI | platform.openai.com | GPT系列 |

**安全注意事项** ⚠️

- **不要把API Key分享给别人**：这东西就是你的"门禁卡"，丢了别人就能用你的额度

- **不要提交到GitHub等公开仓库**：有人专门扫描GitHub找暴露的API Key，然后盗用

- **设置消费上限**：大多数平台都支持设置每月消费上限，避免意外账单

> 💡 **小贴士**：新手建议先用工具内置的免费额度（比如Trae、WorkBuddy都有免费额度），等熟悉了再考虑购买API Key。

### MCP：AI的"工具箱"

**是什么？**

MCP，全称`Model Context Protocol`，是一个让AI能调用外部工具的协议。你可以理解为AI的"工具箱"——没有工具箱，AI只能动嘴皮子；有工具箱，AI就能真正"动手"干活。

**为什么重要？**

这是AI从"建议者"变成"执行者"的关键一步。

没有MCP时：

> 你："帮我写个查询用户数据的SQL"  
> AI：给你写出SQL语句  
> 你：自己复制去执行

有MCP时：

> 你："帮我查一下用户表有多少条数据"  
> AI：直接连接数据库，执行查询，返回结果："共12,345条数据"

**常见MCP有哪些？**

|  |  |
| --- | --- |
| MCP | 能做什么 |
| **MySQL MCP** | AI直接操作数据库，查数据、增删改都行 |
| **Playwright MCP** | AI控制浏览器，自动化测试、网页截图 |
| **GitHub MCP** | AI帮你管理代码仓库，提交代码、创建Issue |
| **文件系统MCP** | AI直接读写你的电脑文件 |

**和Skill的区别**

MCP和Skill很容易混淆，简单区分一下：

- **MCP = AI的"手脚"**：让AI能操作外部工具（数据库、浏览器等）

- **Skill = AI的"技能"**：让AI更擅长某类任务（写测试、代码审查等）

类比：MCP是给AI装上"手"和"脚"，让它能干活；Skill是教AI一些"专业技能"，让它干得更好。

> 💡 **小贴士**：刚入门先不用管MCP，等熟悉了基础功能再配置也不迟。

### Skill：AI的"技能包"

**是什么？**

Skill是AI的"技能包"，用来扩展AI在特定领域的能力。就像给手机装APP——手机本身能打电话，装了微信就能聊天，装了抖音就能刷视频。

**为什么重要？**

有了Skill，AI在特定任务上会表现得更好。比如：

- 装了"代码审查Skill"，AI审代码更专业

- 装了"测试生成Skill"，AI写测试用例更快

- 装了"文档生成Skill"，AI写文档更规范

**常见Skill有哪些？**

|  |  |
| --- | --- |
| Skill | 作用 |
| **代码审查Skill** | AI更擅长Review代码，发现潜在问题 |
| **测试生成Skill** | AI自动生成单元测试、集成测试 |
| **文档生成Skill** | AI自动生成项目文档、API文档 |
| **代码格式化Skill** | AI帮你保持代码风格一致 |

**怎么用？**

不同的工具安装Skill的方式不同：

- 在Trae里有独立的**Skills**系统，可在设置中创建或从社区安装

- 在WorkBuddy里直接使用技能市场

- 在OpenClaw里有ClawHub市场，5700+社区Skill可选

> 💡 **小贴士**：不要贪多。先用默认功能，觉得哪方面不够强了，再针对性加Skill。

# 第二模块：IDE类工具

> **温馨提示**：IDE类工具是所有AI编程工具中门槛最低的。如果你从来没接触过这类工具，从这里开始准没错。想象一下，你在一个超级智能的编辑器里，一边跟AI聊天，一边看着代码自动写出来——是不是很酷？让我们开始吧！

## 开篇：什么是IDE类AI编程工具？

在正式动手之前，我们先用两句话搞清楚一件事。

**IDE是什么？** IDE就是「集成开发环境」的英文缩写。你可以把它理解成一个专门用来写代码的编辑器，比记事本强大得多。我们熟悉的VS Code就是最典型的IDE。

**IDE类AI编程工具又是什么？** 就是在IDE里直接内置了AI能力。你不用再打开ChatGPT问问题然后手动复制代码回来，而是直接在编辑器里跟AI对话，让它帮你写代码、改代码、解释代码。

**这类工具的核心优势：**

- ✅ **所见即所得**：写代码和用AI在同一界面，不用来回切换

- ✅ **零学习成本**：会打字就会用，不需要记复杂命令

- ✅ **项目级理解**：AI能看懂你整个项目的结构，不是只看到一小段代码

- ✅ **修改方便**：AI写的代码直接就在文件里，你可以随时修改

### Skills管理

#### 什么是Skills？

Skills（技能）是AI的**结构化行为设计包**，通过渐进式加载机制为AI注入领域知识和工作流程。它不是简单的提示词，而是围绕任务、工具、流程和输出边界的完整规范。

2025年12月，Anthropic将Skill规范作为开放标准发布，目前已被33+个Agent产品采纳，包括Claude Code、Cursor、GitHub Copilot、VS Code等。

#### Skill与Prompt的本质区别

|  |  |  |
| --- | --- | --- |
| 对比维度 | Prompt | Skill |
| 生命周期 | 单次有效，用完即失 | 永久保存，可反复调用 |
| 结构化程度 | 自由文本，无固定格式 | 标准化SKILL.md文件 |
| 复用性 | 无法复用，每次需重写 | 全局/项目级复用 |
| 执行精度 | 理解模糊，输出波动 | 严格按规则执行，输出稳定 |
| Token消耗 | 每次都要完整加载 | 三层渐进式加载，节省90% |

#### 三层渐进式加载机制

这是Skill规范最精妙的设计，借鉴了渐进式信息披露策略：

|  |  |  |  |
| --- | --- | --- | --- |
| 层级 | 加载内容 | 加载时机 | Token消耗 |
| L1 目录层 | name + description | 会话启动时 | 每个Skill约50-100 tokens |
| L2 指令层 | 完整SKILL.md body | Skill被激活时 | 建议<5000 tokens |
| L3 资源层 | scripts/、references/、assets/中的文件 | 指令引用时按需 | 视文件大小 |

**关键价值**：即使安装了20个Skill，初始加载也仅1000-2000 tokens。相比单体式提示词，上下文使用量减少约90%。

Skill的触发完全依赖description字段，由模型自主判断当前任务是否匹配（Model-driven Activation），而非关键词硬编码匹配。

### MCP管理

#### 了解MCP是什么

**MCP（Model Context Protocol，模型上下文协议）** 是 Anthropic 在 2024 年 11 月推出的一个开放标准协议，用于连接 AI 模型与外部数据源和工具。

简单来说，MCP 就像是 **AI 的"USB-C 接口"** —— 它提供了一种标准化的方式，让 AI 助手能够安全、统一地访问各种外部资源。

**核心架构**

#### MCP 的三大核心概念

|  |  |  |
| --- | --- | --- |
| 概念 | 说明 | 示例 |
| **Resources（资源）** | 提供数据读取能力，类似"文件读取" | 读取数据库表结构、读取文件内容 |
| **Tools（工具）** | 提供操作执行能力，类似"函数调用" | 执行 SQL 查询、操作浏览器 |
| **Prompts（提示词）** | 预定义的交互模板 | 代码审查模板、数据分析模板 |

#### 为什么需要 MCP？

没有 MCP 之前的问题：

- 每个 AI 应用都需要为每个工具写专门的集成代码

- 工具提供商需要为每个 AI 平台单独适配

- 安全性难以保证，权限控制分散

有了 MCP 之后：

- ✅ **标准化**：一次开发，到处使用

- ✅ **安全性**：用户完全控制哪些工具可以被访问

- ✅ **可扩展**：随时添加新的 MCP Server

- ✅ **解耦**：AI 应用和工具独立发展

#### 没有MCP时 vs 有MCP时

没有MCP时：

> 你："帮我写个查询用户数据的SQL"  
> AI：给你写出SQL语句  
> 你：自己复制去执行

有MCP时：

> 你："帮我查一下用户表有多少条数据"  
> AI：直接连接数据库，执行查询，返回结果："共12,345条数据"

- FastMCP 框架

**定义****：FastMCP 是一个用于构建** **MCP（Model Context Protocol）服务** **的 Python 框架。**

**核心作用****：**

- **允许 AI 模型调用外部工具（Tool）和访问资源（Resource）**
- **实现 AI 与外部系统的安全交互**
- **支持多种传输协议（stdio、sse）**

**基本使用模式****：**

**先下载模块：**`pip install fastmcp -i https://pypi.tuna.tsinghua.edu.cn/simple`

- @mcp.tool() - 工具函数

**定义****：将函数注册为 AI 可调用的****工具****。**

**特点****：**

- **主动调用****：AI 需要显式调用** `call_tool("工具名", 参数)`
- **支持参数****：可以接收输入参数**
- **执行操作****：适合执行任务、计算、查询等**
- **返回结果****：返回处理后的结果给调用者**

**示例****：**

- @mcp.resource("uri") - 资源

**定义****：将函数注册为可通过** **URI** **访问的****资源****。**

**特点****：**

### 基本使用

**打开Agent面板**

按快捷键 `Cmd/Ctrl + I`，打开Agent面板。Agent可以自主完成复杂的编码任务：搜索代码库、编辑文件以及运行终端命令。

**三种模式**

| Ask | 你只是问AI问题，不让它改代码 |
| Plan | 先规划，后编码 |
| Agent | 让AI自主完成复杂任务 |
| Debug | 专门查 Bug |
| Multitask | 并行多任务 |

**计划模式（Plan Mode）**

在Agent输入框中按下 `Shift+Tab` 切换到计划模式。此时AI不会立刻写代码，而是会：

1. 在你的代码库中检索以找到相关文件

1. 就你的需求提出澄清性问题

1. 创建详细的实现计划

1. 在开始构建前等待你的确认

点击「Save to workspace」将计划保存到 `.cursor/plans/` 中，为团队创建文档，也为后续工作提供上下文。

Plan 模式最适合：

- 具有多种可行方案的复杂功能
- 涉及大量文件或系统的任务
- 需求不清晰、需要先探索再弄清工作范围的任务
- 你希望先审查整体方案的架构决策

中间会有提问，按需求选择即可。没有特定要求

**Agent 模式**

你不需要在提示里手动标记每一个文件。Agent具有强大的搜索功能，会按需提取上下文。当你询问"认证流程"时，Agent会通过搜索找到相关文件——即使你的提示中没有包含这些文件的准确文件名。

保持简单：如果你知道确切的文件，就用 `@` 标记它；如果不知道，就交给Agent去找。

**知道何时重新开始对话**

过长的对话可能会让Agent偏离重点。在以下情况下请开启一个新的对话：

- 你要开始处理不同的任务或功能

- Agent看起来很困惑，或反复犯同样的错误

- 你已经完成了一个逻辑完整的工作单元

在新对话中使用 `@Past Chats` 引用之前的工作，而不是把整个对话复制粘贴过来。

**Debug 模式**

调试模式帮助你定位问题根源，并修复那些难以复现或理解的棘手错误。智能代理不会立刻编写代码，而是先生成假设、添加日志语句，并利用运行时信息精确定位问题，然后再进行有针对性的修复。

Debug Mode 最适合用于：

- **你能复现但搞不清原因的 bug**：当你知道有问题，但光看代码看不出原因时
- **竞争条件和时序问题**：依赖执行顺序或异步行为的问题
- **性能问题和内存泄漏**：需要运行时分析才能理解的问题
- **曾经能用但现在失效的回归问题**：当你需要追踪到底改了什么时

当标准 Agent 交互难以解决某个 bug 时，Debug Mode 会基于运行时证据，而不是凭猜测来给出修复方案，提供一种不同的排查方式。

>
> 点击`Mark as fixed`按钮结束 debug 模式

1. **图形界面（GUI）**：就是你平时看到的窗口、按钮、图标。用鼠标点点点就能完成任务。

1. **命令行界面（CLI）**：一个黑漆漆的窗口，里面只有文字。所有操作都要靠输入文字命令来完成。

Claude Code 是由 Anthropic 公司官方推出的命令行AI编程工具。根据The Pragmatic Engineer 2026年3月对906名开发者的调研，**Claude Code以46%的用户最爱度遥遥领先**，远超Cursor（19%）和GitHub Copilot（9%）。在中小公司中的采用率高达**75%**。

**核心优势：**

- **Claude模型原生加持**：继承Claude Opus 4.6顶级代码能力，200K token超大上下文

### Hooks（钩子）

Hooks是Claude Code的"自动化传感器"，在特定事件发生时自动执行脚本，实现100%可靠的自动化。

**为什么需要Hooks？**

没有Hooks之前，你只能靠AI"记住"你的要求：

有了Hooks之后，自动化100%可靠，不需要AI记住，事件触发就执行。

**配置位置**

Hooks配置在settings.json文件中，有三个级别：

|  |  |  |
| --- | --- | --- |
| 位置 | 作用范围 | 优先级 |
| `.claude/settings.local.json` | 项目级（不提交到git） | 最高 |
| `.claude/settings.json` | 项目级（提交到git，团队共享） | 中等 |
| `~/.claude/settings.json` | 用户级（所有项目生效） | 最低 |

**基本配置结构**

配置字段说明：

|  |  |  |
| --- | --- | --- |
| 字段 | 必填 | 说明 |
| `matcher` | 是 | 工具名称或正则表达式（如 `"Read"`、`".*"`） |
| `event` | 是 | 触发时机：`PreToolUse`、`PostToolUse`等 |
| `type` | 是 | `"command"`（执行脚本）或 `"prompt"`（LLM评估） |
| `command` | type=command时必填 | 要执行的shell命令 |
| `prompt` | type=prompt时必填 | LLM评估的提示词模板 |

**Hook事件类型**

|  |  |  |
| --- | --- | --- |
| 事件类型 | 触发时机 | 典型用途 |
| **PreToolUse** | 工具执行前 | 拦截危险命令、验证文件路径、自动批准安全操作 |
| **PostToolUse** | 工具执行后 | 运行格式化、触发linter、记录文件变更 |
| **UserPromptSubmit** | 用户提交提示词时 | 注入上下文、验证请求、添加动态信息 |
| **PermissionRequest** | 请求权限时 | 自动批准/拒绝特定操作 |
| **SessionStart** | 会话开始时 | 注入git状态、加载TODO列表、设置环境上下文 |
| **SessionEnd** | 会话结束时 | 清理、保存状态、生成报告 |
| **Stop** | AI停止响应时 | 验证任务完成、运行测试、生成摘要 |
| **SubagentStop** | 子代理完成时 | 验证子代理输出、触发后续操作 |
| **PreCompact** | 上下文压缩前 | 备份重要信息、保存关键决策 |
| **PostCompact** | 上下文压缩后 | 验证压缩状态、更新外部状态 |
| **StopFailure** | API错误导致停止时 | 错误告警、重试逻辑、记录API失败 |
| **Notification** | 系统通知时 | 自定义日志、告警、错误处理 |

**Hook的最佳实践**

1. **从简单开始**：先配置自动批准Read操作，熟悉流程
2. **使用command类型**：对于简单规则，command比prompt更快
3. **使用prompt类型**：对于复杂判断，利用LLM的智能
4. **设置超时**：避免Hook执行时间过长影响体验
5. **注意安全**：不要自动批准危险操作，如rm、curl等

> 同一家公司（代码仓库），开了多个独立办公室（worktree）。每个办公室有自己的白板、自己的进度板，员工互不干扰；但所有人共享同一个档案室（`.git`），文件历史都在那里统一存放。

### 错误三：不给上下文

❌ "这个报错了"  
✅ "Python 3.11，执行 pip install 时报错：[粘贴报错信息]"

### 错误四：不验证结果

AI生成的代码一定要：

1. 阅读并理解

1. 运行测试

1. 检查边界情况

### 错误五：不迭代优化

不要指望一次完美，要：

1. 先让AI生成初稿

1. 审查并指出问题

1. 让AI修改

1. 重复直到满意
