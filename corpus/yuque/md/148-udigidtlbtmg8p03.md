**1. post和put区别**

- **功能用途**：`POST` 一般用于创建资源，向服务器提交数据以创建新的实体，例如在论坛中发布新帖子。`PUT` 主要用于更新资源，它通常要求请求中包含完整的资源表示，用于替换服务器上已有的资源，比如更新用户的个人信息。
- **幂等性**：`PUT` 方法是幂等的，多次对同一资源执行相同的 `PUT` 请求，结果与一次请求相同，不会产生额外的影响。而 `POST` 方法不是幂等的，多次提交相同的 `POST` 请求可能会创建多个相同的资源。
- **资源标识**：`PUT` 请求的 `URL` 一般指向具体的资源，明确指定要更新的资源的位置。`POST` 请求的 `URL` 可以指向资源集合，由服务器决定如何处理提交的数据来创建新资源。

**2. 冒泡排序**  
冒泡排序（Bubble Sort）是一种简单的比较排序算法。它重复地走访过要排序的数列，一次比较两个元素，如果它们的顺序错误就把它们交换过来。走访数列的工作是重复地进行直到数列不再需要交换，也就是说该数列已经排序完成。

**3. 快速排序**  
快速排序（Quick Sort）采用分治法的思想。它选择一个基准元素，将数组分为两部分，使得左边部分的元素都小于基准元素，右边部分的元素都大于基准元素，然后分别对左右两部分递归地进行排序。

**4. 堆排序**  
堆排序（Heap Sort）是指利用堆这种数据结构所设计的一种排序算法。堆是一个近似完全二叉树的结构，并同时满足堆积的性质：即子结点的键值或索引总是小于（或者大于）它的父节点。

**5. 堆和栈在计算机组成里的区别，说说堆的数据结构**

- **堆和栈在计算机组成里的区别**：

- **分配方式**：栈由操作系统自动分配释放，存放函数的参数值、局部变量等；堆是由程序员分配和释放，若程序员不释放，程序结束时可能由操作系统回收，用于动态内存分配。
- **空间大小**：栈的空间大小相对较小且固定，一般在几 MB 以内；堆的空间大小灵活，可根据程序的需要动态扩展或缩小。
- **生长方向**：栈的生长方向是向下的，即向着内存地址减小的方向；堆的生长方向是向上的，向着内存地址增大的方向。

- **堆的数据结构**：堆是一种特殊的完全二叉树，分为大顶堆和小顶堆。大顶堆中每个节点的值都大于或等于其左右孩子节点的值；小顶堆中每个节点的值都小于或等于其左右孩子节点的值。

**6. 进程和线程的区别**

- **定义**：进程是程序在操作系统中的一次执行过程，是资源分配的基本单位；线程是进程中的一个执行单元，是 CPU 调度的基本单位。
- **资源分配**：进程拥有独立的地址空间、代码段、数据段等资源，不同进程之间的资源相互独立；线程共享所属进程的资源，如内存空间、文件描述符等，但有自己独立的栈空间、程序计数器等。
- **上下文切换**：进程的上下文切换开销较大，因为需要保存和恢复整个进程的状态；线程的上下文切换开销较小，因为只需要保存和恢复线程自己的少量状态信息。
- **并发性**：进程之间可以并发执行，也可以并行执行；线程之间也可以并发执行，而且在多处理器系统中，同一进程内的多个线程可以并行执行。

**7. 锁和信号量的区别**

- **功能用途**：锁主要用于保护临界区，确保同一时间只有一个线程（或进程）能够访问共享资源，防止数据竞争和不一致；信号量不仅可以用于保护临界区，还可以用于控制对资源的访问数量，例如限制同时访问某个文件的线程数。
- **计数方式**：锁一般只有两种状态，锁定和未锁定；信号量是一个计数器，可以有任意的整数值，通过对计数器的操作来控制对资源的访问。
- **释放方式**：锁必须由获得锁的线程（或进程）来释放；信号量的释放可以由任意线程（或进程）来进行，只要符合信号量的操作规则。

**8. 为什么给线程绑定能够优化性能**  
线程绑定（Thread Binding），也称为线程亲和性（Thread Affinity），是指将线程固定在特定的 CPU 核心上运行。这样做可以减少 CPU 缓存的失效次数，因为线程固定在一个 CPU 核心上运行时，其访问的数据会更多地保留在该核心的缓存中，减少了缓存缺失的开销。同时，避免了线程在不同 CPU 核心之间频繁迁移带来的上下文切换开销，提高了 CPU 的利用率，从而优化了性能。

**9. 描述 OSI 七层网络模型**

- **物理层**：负责在物理介质上传输原始的比特流，定义了物理设备的接口标准、传输介质的特性等，如电缆的类型、接口的形状等。
- **数据链路层**：将物理层传来的比特流组织成数据帧，进行差错检测和纠正，同时实现数据链路的建立、维护和拆除，如以太网协议。
- **网络层**：负责将数据帧从源主机传输到目标主机，通过路由选择算法确定最佳路径，处理网络拥塞、网络互联等问题，如 IP 协议。
- **传输层**：为应用层提供端到端的可靠或不可靠的数据传输服务，主要协议有 TCP 和 UDP，TCP 提供可靠的面向连接的服务，UDP 提供不可靠的无连接的服务。
- **会话层**：负责建立、管理和终止应用程序之间的会话连接，如会话的建立、同步、恢复等。
- **表示层**：对数据进行转换、加密和解密、压缩和解压缩等处理，以确保不同系统之间能够正确地理解和处理数据。
- **应用层**：为用户提供各种网络应用服务，如 HTTP、FTP、SMTP 等协议，直接面向用户的应用程序。

**10. tcp和udp**  
TCP（Transmission Control Protocol，传输控制协议）是一种面向连接的、可靠的、基于字节流的传输层通信协议。它在传输数据之前需要先建立连接，通过三次握手确保连接的可靠性，数据传输过程中进行流量控制和差错控制，保证数据的有序传输。

UDP（User Datagram Protocol，用户数据报协议）是一种无连接的、不可靠的传输层协议。它不需要建立连接，直接将数据报发送出去，不保证数据的可靠传输和有序到达，但传输速度快，适用于对实时性要求较高的应用，如视频流、音频流等。

**11. tcp三次握手，为什么要三次握手**  
TCP 三次握手的过程如下：

- 第一次握手：客户端发送一个带有 SYN（同步序列号）标志的 TCP 报文段到服务器，进入 SYN\_SENT 状态。
- 第二次握手：服务器收到客户端的 SYN 报文段后，向客户端发送一个带有 SYN 和 ACK（确认序列号）标志的 TCP 报文段，进入 SYN\_RCVD 状态。
- 第三次握手：客户端收到服务器的 SYN + ACK 报文段后，向服务器发送一个带有 ACK 标志的 TCP 报文段，进入 ESTABLISHED 状态，服务器收到该报文段后也进入 ESTABLISHED 状态，连接建立成功。

需要三次握手的原因主要是为了确保双方都具有接收和发送数据的能力，并且能够可靠地建立连接。通过三次握手，客户端和服务器都能确认对方的接收和发送能力，避免了因网络延迟等原因导致的错误连接和资源浪费。

**12. tcp和udp的常用协议**

- **TCP 的常用协议**：

- **HTTP（超文本传输协议）**：用于在 Web 浏览器和 Web 服务器之间传输超文本数据，是互联网上应用最广泛的协议之一。
- **SMTP（简单邮件传输协议）**：用于发送电子邮件，将邮件从发件人的邮件服务器传输到收件人的邮件服务器。
- **FTP（文件传输协议）**：用于在网络上进行文件的上传和下载，提供了可靠的文件传输服务。

- **UDP 的常用协议**：

- **DNS（域名系统）**：用于将域名解析为 IP 地址，DNS 查询通常使用 UDP 协议，因为 DNS 查询的数据量较小，对实时性要求较高。
- **DHCP（动态主机配置协议）**：用于自动分配 IP 地址和其他网络配置参数，客户端和服务器之间通过 UDP 协议进行通信。
- **SNMP（简单网络管理协议）**：用于网络设备的管理和监控，通过 UDP 协议进行数据传输。

**13. Linux 相关 ssh是什么协议**  
SSH（Secure Shell）是一种网络协议，用于在不安全的网络中建立安全的远程连接。它提供了加密的通信通道，可用于远程登录、文件传输等操作。SSH 协议基于 TCP 协议，默认使用 22 端口。通过 SSH，用户可以在本地计算机上远程登录到 Linux 服务器或其他支持 SSH 的设备，进行命令行操作、文件管理等，并且数据传输过程是加密的，保证了数据的安全性和隐私性。

**19. 场景题 微信朋友圈点赞功能梳理测试点**

- **功能测试**：

- 能否对朋友圈的内容进行点赞操作，点赞后点赞数是否正确增加。
- 能否取消点赞，取消点赞后点赞数是否正确减少。
- 对同一内容多次点赞，点赞数是否只增加一次。
- 点赞自己发布的内容，是否有相应提示或处理。
- 点赞已删除的朋友圈内容，是否有正确的提示。

- **界面测试**：

- 点赞按钮的位置、样式、大小是否符合设计要求。
- 点赞数的显示是否清晰、准确，位置是否合适。
- 点赞后的状态变化（如按钮颜色、图标变化）是否正常显示。

- **性能测试**：

- 在大量用户同时点赞的情况下，系统的响应时间是否在可接受范围内。
- 点赞功能对服务器资源的占用情况，如 CPU、内存等。

- **兼容性测试**：

- 在不同操作系统（如 iOS、安卓）和不同版本的微信上，点赞功能是否正常工作。
- 在不同屏幕尺寸和分辨率的设备上，点赞按钮和点赞数的显示是否正常。

- **安全性测试**：

- 是否存在用户可以通过非法手段（如篡改数据）增加点赞数的情况。
- 用户的点赞操作是否会泄露个人隐私信息。

- **易用性测试**：

- 点赞操作是否简单易懂，用户是否容易找到点赞按钮。
- 对于误点赞的情况，取消点赞的操作是否方便。

**20. 链表，栈，队列**

- **链表**：是一种线性数据结构，由一系列节点组成，每个节点包含数据和指向下一个节点的指针（单链表）或指向前一个节点和下一个节点的指针（双链表）。链表的优点是插入和删除操作效率高，不需要移动大量数据；缺点是访问元素需要顺序遍历，时间复杂度较高。
- **栈**：是一种后进先出（LIFO，Last In First Out）的数据结构，只能在一端进行插入（压栈）和删除（弹栈）操作。栈的应用场景包括函数调用栈、表达式求值等。
- **队列**：是一种先进先出（FIFO，First In First Out）的数据结构，在一端进行插入（入队）操作，在另一端进行删除（出队）操作。队列的应用场景包括任务队列、打印队列等。
