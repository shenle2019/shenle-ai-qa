## 框架介绍

### API自动化框架

#### 简单介绍：

我们这套自动化框架主要基于 Python 技术栈，集成了 Requests、Excel、Allure 和 Pytest 这些成熟工具。

整体采用了分层架构设计，分五个核心模块：用例管理、关键字驱动、用例解析、核心运行和工具集。最大的亮点是用 Excel/YAML 写用例，业务同事不懂代码也能快速上手；基于pytest进行了二次拓展，支持了自定义命令进行启动。还有关键字封装，让用例像搭积木一样简单组合。

我们会部署到 Jenkins 做定时任务，自动生成 Allure 测试报告，并同步推送到企业微信和邮箱。

后续我们也设计了将框架打包成exe文件，直接用命令行进行运行,更简单便捷

#### 详细介绍:

我们这套自动化框架基于 Python 技术栈，核心用了 Requests、Excel、Allure 和 Pytest 这些工具。整体采用了分层架构，一共五层，我来简单介绍一下：

**最上层是用例管理层**，支持 YAML 和 Excel 两种格式，实际工作中都可以使用，如果业务测试同事可能不太懂代码，用表格填写用例就能快速上手。

**第二层是关键字驱动层**，我们把所有底层操作都封装成了关键字，比如发送请求、断言、等待、数据库操作这些。写用例就像搭积木一样，直接组合关键字就能完成复杂场景，避免重复写底层代码。

**第三层是用例解析层**，专门解析不同格式的用例，我们抽了个基类，符合开闭原则，后续要扩展新格式也很方便。

**第四层是核心运行层**，相当于框架的发动机，调度整个用例运行流程。我们还设计了全局变量管理，用来传递 token、接口返回数据这些共享信息，同时基于pytest进行了二次拓展，支持了自定义命令进行启动。

**最底层是工具集层**，包括时间处理、随机数据生成这些通用方法，避免代码重复。

最后，我们会部署到 Jenkins 做定时任务，自动运行用例，生成 Allure 测试报告，并自动推送到企业微信和邮箱，实现全程自动化。

​

## 个人职责说明:

### 10K附近薪资:

> 角色背景：主要是参与框架的测试用例的维护和协作测试组长进行框架的维护。（ **偏执行、维护、配合组长** ）

我现在主要做的是接口、Web、App 自动化这块，框架的维护和部分核心功能开发都在我的工作范围内。

这个框架搭建的初衷就是要易用、灵活、好维护，让不懂代码的业务测试同学也能快速上手。所以设计上是把用例和代码彻底分开，业务同学完全不用写代码就能做自动化。

我在里面主要做的就是几件事：

**数据驱动相关开发**，大部分时间是用 Excel/YAML 来维护，完成数据读取传递这些开发工作

关键字编写开发，更新一些关键字、修复简单的执行问题，及时进行对应的拓展。

常规的CI/CD流程配置部署工作，比如发送到企业微信，邮箱，自动执行测试这些流程

总体来说 , 我的核心工作就是负责框架中间这几个关键环节的开发，并且负责后续的更新维护。

​

### 10-15K：

> 角色背景：主导公司的框架核心流程的开发和维护工作（核心代码逻辑的编写）

#### 简单介绍：

在上家公司我独立搭建了接口、Web、App 自动化框架，全程负责架构设计和落地实现。

技术栈用的 Python + Requests/Selenium/Appium + Excel + Allure + Pytest。核心目标就是让不会代码的同事也能做自动化，所以整体设计很注重易用性和可维护性。

我在里面主要做的是这几件事:

- 核心代码实现：文件解析类支持 Excel、Yaml 格式；核心执行器 TestRunner 负责调度执行；设计了 globalContext 解决参数关联问题；封装了 VarRender 做变量替换；优化了 Allure 报告展示；还封装了 CasesPlugin 类方便灵活执行
- 配合运维集成 Jenkins，现在框架已经在项目中落地使用，后续扩展只需要维护关键字方法就行，提升了回归效率和线上巡检效率。

​

#### 详细介绍：

在上家公司，我独立搭建了一套覆盖接口、Web、App 的自动化框架，从架构设计到落地都是我负责的。

**技术栈用的主要是**：Python，接口这块用 Requests，Web 用 Selenium，App 用 Appium，配合 Excel 做数据驱动，Allure 做测试报告，Pytest 作为测试框架。

**搭这个框架的核心目标**：就是要让团队里不会代码的同学也能做自动化，所以整个设计都围绕"易用、灵活、好维护"这三个点来的。

**整体架构**：我采用了分层设计，结合了关键字驱动和数据驱动，把框架分成六大块：用例管理层、关键字驱动层、用例解析层、核心运行层、工具集层，还有一个报表层。

**我的主要工作包括：**

**架构设计这块**：整体框架的分层和模块划分都是我定的。

**代码实现这块**，我做了几件事：

- 写了文件解析类，支持 Excel、Yaml 这些不同格式的用例文件，后面如果要扩展新格式也方便
- 核心执行器层的逻辑是我处理的，TestRunner 基于读取出来的测试数据，结合关键字驱动进行调度执行。还设计了 globalContext 用来存全局变量，解决用例参数关联的问题。工具类里封装了 VarRender 方便做变量替换
- 报告这块也做了优化，用 Pytest 调度需要执行的用例，结合日志工具和 Allure 生成测试报告，看起来更直观
- 为了执行方便，还用了 pytest 的钩子函数封装了个 CasesPlugin 类，可以灵活指定用例类型、用例路径和关键字方法路径

**落地这块**：框架搭完之后，配合运维集成到 Jenkins 做 CI/CD。现在整个框架已经在项目里落地使用了，团队直接就能用上自动化。后续要扩展的话，只需要维护关键字方法，按照用例模板写用例就行，大大提升了回归效率和线上巡检的速度。

### 15-25K：

> ​**背景设定：**首先你是一个能带团队、主导设计、多项目落地。同时你可以把这个框架应用在多个项目当中，尽可能往三端合一的思路去进行扩展。 首先你要确定目前有多少个项目用到这个框架**（这个自由发挥结合你的公司确定）**、你做框架是多少人？**（2-3人，其它测试人员维护用例）**用了多长的时间？**（整个框架因为还有别的工作任务，断断续续花费了2个月不到的样子，后续主要就是功能测试组的小伙伴进行用例的维护。）**

#### 框架介绍：

在上家公司，我是自动化框架搭建的核心负责人，带领一个3人团队，针对自动化门槛高、维护性差、多端不兼容的痛点，设计并落地了一套基于关键字驱动的多端自动化框架。

技术选型用的 Python + Selenium/Appium/Requests + Allure + Excel/YAML + Pytest。

架构上我设计了一个6层分层架构：用例管理、关键字驱动、用例解析、核心运行、工具集、报表。团队分工上，我负责整体方案设计和核心代码，团队成员负责工具集、规范制定和项目落地，同时我还做了培训和框架推广。

比较有特色的地方在于以下几个点：

1. 数据驱动这块，我们采用了 pytest的钩子函数来实现数据驱动，这样可以根据我们文件夹中的多个用例去参数化执行。
2. 同时我们框架支持各种不同文件类型的加载，比如excel,yaml.后续可以直接拓展任意的文件做数据驱动
3. 关键字这块，我们的封装实现了关键字的自动加载，如果实际执行过程中出现需要自定义的关键字而源码不包含也可以直接在外部文件定义。
4. 二次封装了pytest，在入口处添加了自定义启动参数，从而让我们的框架能够纯命令化执行。
5. 针对测试报告的美化，我们引入了日志工具和 Allure 生成测试报告，让测试报告更加美观
6. 在UI自动化方面，除了图片外，还引入了录像机制，可以更清楚复现执行过程
7. 加入了AI元素，针对UI界面，支持自然语言编写测试用例，自然语言断言这块的机制。

最终成果是：非开发背景的测试人员可以直接写用例，不用碰代码；用例维护效率提升60%以上，维护成本降低50%；框架在多个项目稳定落地，回归测试效率提升70%，大幅减少了重复人工测试工作量。
