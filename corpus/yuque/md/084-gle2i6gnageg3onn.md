# 实操场景: 如何在物联网(硬件)平台完成性能测试

## **1. 硬件通信的复杂性**

- **难点1：TCP协议的长连接特性**

- **一般场景是这样的： 每个传感器组件，每隔30秒 向服务器平台端，去发送一个常规内容，可以是JSON 可以是 16进制的数字 也可以是xml或者纯字符串 , 告知本传感器在线。 （心跳机制）**
- **服务器：如果一旦超过一段时间没接收到心跳，这时候就会把这个传感器在平台的状态改成下线。**

- TCP协议在jmeter中的应用

​

- **问题**：物联网设备通常通过TCP长连接保持与服务器的实时通信，需维护大量并发连接状态。
- **对比HTTP**：HTTP为短连接（请求-响应后断开），服务器资源占用较低。
- **示例**：

- 智能家居场景中，1000个设备持续发送传感器数据（TCP长连接）。
- 对比电商场景中，1000个用户访问下单接口（HTTP短连接）。

- **难点2：数据包处理复杂度高**

- **问题**：TCP需处理粘包、拆包、数据完整性校验，而HTTP直接解析JSON/XML。
- **示例**：

- 传感器数据流可能因网络波动被拆分为多个包，需自定义协议处理（如长度头+内容）。
- HTTP接口直接通过Content-Length或分块传输处理数据边界。

- **难点3：硬件资源限制**

- **问题**：设备端CPU、内存、网络带宽受限，可能影响通信稳定性。
- **对比HTTP**：客户端（如手机、浏览器）资源充足，性能瓶颈通常集中在服务端。

​

## **2.高并发场景的特殊性**

**服务器压力核心指标**

|  |  |  |
| --- | --- | --- |
| **指标** | **TCP场景** | **HTTP场景** |
| **连接数** | 需支持数万长连接 | 短连接，瞬时并发高但连接数少 |
| **内存占用** | 每个连接占用内存（缓冲区） | 请求处理完成后释放资源 |
| **CPU消耗** | 高频处理数据包（如心跳包） | 集中在业务逻辑处理 |
| **网络带宽** | 持续小流量（如传感器数据） | 突发性大流量（如图片上传） |

- **服务器监控指标**

- **资源层**：CPU使用率、内存占用、TCP连接数
- **应用层**：消息处理延迟、丢包率、错误日志。

- **典型问题与解决方案**

|  |  |
| --- | --- |
| **问题现象** | **可能原因** |
| 连接超时或拒绝 | 服务器端口数或线程池不足 |
| 响应延迟逐渐升高 | 内存泄漏或数据库瓶颈 |
| 数据包不完整 | TCP粘包/拆包未处理 |

## **3.总结与讨论**

1. **物联网性能测试的核心差异**

1. **连接管理**：TCP长连接需关注连接保持、心跳机制、资源泄漏。
2. **协议设计**：需处理二进制数据流，而非HTTP的明文报文。

1. **优化方向**

1. **服务器端**：使用异步I/O模型（如Netty、Go协程），优化TCP参数（如`tcp_tw_reuse`）。
2. **硬件端**：精简通信协议，支持数据压缩与批量上报。

1. 面试思考:

1. 如何测试弱网络环境（如3G/4G抖动）下的设备通信稳定性？
2. 在边缘计算场景中，如何分担服务器压力？

### 网络中的B,bit, MB的换算方式

B是Byte的缩写，B就是Byte，也就是字节（Byte）；

b是bit的缩写，b就是bit，也就是比特位（bit）。B与b不同，注意区分， 1 Byte = 8 bits

KB是千字节，Kb是千比特位。

1MB （兆字节） = 1024KB（千字节）=1024 \* 1024B(字节)=1048576 B(字节)；

1024Byte（字节）=1KB(千字节)

1024KB（千字节）=1MB（兆字节）

1024MB=1GB;

带宽中 10M ，100M，1000M中的效率传输计算

|  |  |  |
| --- | --- | --- |
| 带宽 | 下载速度 | 计算公式 |
| 1MB | 下载速度为：128KB/s | 1/8 =0.12 |
| .2MB | 下载速度为256KB/s | 2/8 = 0.25 |
| 10MB | 下载速度为 1.25MB/s | 10/8 = 1.25 |
| 100MB | 下载速度为12.5MB/s | 100/8 = 12.5 |

为什么要除以8？

在计算机中，下载速度是以字节(B)为单位的，

网络带宽单位的符号是bps（bit/s，位/秒 ，二进制的位传递）以比特(b)为单位的。

比如说: 在网上下载一个软件，都会以B(字节)为单位的，再比如你打开一个网页，这个网页中可能会有图片，文字，视频等内容，这些内容本质上来说，也是下载到你电脑了，然后你才能看到的。

我们申请的带宽是10Mb/s这个单位中的b是小写的，而我们刚才说的1B(字节)=8b(位),这里刚好是8倍的关系，即下载速度：10Mb / 8 = 1.25MB

## 磁盘的操作与性能的影响

在接口请求过程中，除了对服务器的查询之外，还涉及到其他类型的操作，比如写数据，修改数据，记录日志，文件上传等各种操作，这些数据因为能永远保留在电脑中。所以这种做法就叫**持久化**。一般持久化的数据，只要我们不去动用手法去删除，它就会一直存在。而它存储的位置,就是咱们所说的磁盘.

​

### 内存与磁盘的区别

- 磁盘是什么?

磁盘一般又叫硬盘，它就是用来存储一些数据的。

机械硬盘(HDD):

工作原理： 机械臂和磁盘转动，读写

性能角度：读写速度慢和延迟比较高。

特点：便宜，容量大 ，速度慢，寿命短。

​

固态硬盘(SSD):

工作原理：使用闪存芯片去存储数据

性能角度：高速读写和低延迟

特点：贵，速度快，寿命相对长一点

​

磁盘与内存的关系？

​

它们都是用来存数据的，但是内存一般都是缓存，即，如果断电重启，对应的内存存放的东西就会被回收。

​

每台电脑内存的数量是有限的，比磁盘存放的东西要小很多

通过这样的描述，我们大概就能够知道一个核心问题了，一个请求，发送的过程中，如果涉及到数据操作的，这时候程序就会向磁盘里去写数据，而一个请求的结束，通常都是这个数据被写入完毕（操作成功）从而来结束请求. 所以，对于数据写入的速度快慢，它会很明显的影响到咱们的系统性能.

所谓的磁盘操作，最关键的就是检查磁盘的读写速度，与文件数据的大小对比，我们可以得到一个比较清晰的认知，当前接口是否可以优化，在硬件不可变的情况下，能否通过代码减少这种大量的磁盘读取

​

## 磁盘性能测试手法

**dd命令**，测试磁盘的IO速度，确认磁盘写入速度，读取速度，我们就能推出耗费时间。

这个命令损伤硬盘，不建议长时间测试.

同一型号的硬盘，测试一块就行。

命令：dd开头

time dd if=/dev/zero of=/dev/sda1 bs=8k count=10000 oflag=dsync

**这里注意** ：oflag=dsync 每次都要持久化到硬盘， 因为写数据的时候，会经过内存，有可能被内存 暂存了，为了防止这个情况，只体现出磁盘的标准性能，我们需要用dsync 因为这样，会等待文件完整写入
