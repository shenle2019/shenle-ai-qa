# 阶段十六。鸿蒙 OS 专项测试命令行工具详解

## 一、SmartPerf Device 性能工具使用指导

### 1.1 工具简介

**工具定位**：  
鸿蒙系统级性能功耗测试工具，支持**实时指标监测、数据持久化分析及界面可视化截图**，适用于应用开发、整机测试及版本迭代场景。

**核心指标**：

|  |  |  |  |
| --- | --- | --- | --- |
| **指标** | **单位** | **采集频率** | **功能描述** |
| CPU 频率 / 使用率 | Hz/% | 1 次 / 秒 | 大中小核资源占用，过高导致发烫 |
| GPU 频率 / 负载 | Hz/% | 1 次 / 秒 | 图形处理压力，过高导致性能下降 |
| FPS/Jitters | fps/ns | 1 次 / 秒 | 画面流畅度，Jitters 反映帧率稳定性 |
| 内存（RAM） | KB | 1 次 / 秒 | 进程物理内存占用，监测泄漏风险 |
| 温度（TEMP） | ℃ | 1 次 / 秒 | GPU 与系统芯片温度，评估散热设计 |
| 屏幕截图 | - | 1 次 / 2 秒 | 界面可视化分析，存储于`/capture` |

### 1.2 实现原理

**架构分层**：

**关键机制**：

- **数据通道**：通过 Unix Domain Socket 实现端间通信，传输协议为 JSON 格式；
- **权限控制**：Daemon 端需`ohos.permission.GET_PERFORMANCE_DATA`权限；
- **异常处理**：支持采集超时中断（默认 30 分钟）与进程守护重启。

### 1.3 约束与限制

1. **系统要求**：仅支持 API 9 + 设备，需预置`smartperf_daemon`进程；
2. **环境依赖**：

- HDC 工具版本≥3.0.0，通过`hdc version`验证；
- 设备需开启 “开发人员选项” 并授权调试，`hdc list targets`需显示设备 SN；

1. **操作限制**：

- 截图功能仅支持有屏设备；
- `-VIEW`参数需与被测应用图层名称完全匹配（如`DisplayNode`）。

**三维测试体系**：

|  |  |  |  |
| --- | --- | --- | --- |
| **模式** | **事件类型** | **覆盖范围** | **核心目标** |

### 2.4 结果分析工具箱

1. **崩溃日志定位**：

- 搜索`wukong.log`中的`Exception`关键词，提取堆栈信息；
- 示例：`AndroidRuntime: FATAL EXCEPTION: main`指向主线程崩溃。

1. **性能关联分析**：

- 对比 SmartPerf 的`data.csv`，查看测试期间内存 / CPU 峰值是否与崩溃时间点重合；
- 若`memTotal`在测试中增长 50% 以上，可能存在内存泄漏。

### 3.2 自定义指标扩展

**支持二次开发点**：

- **新增指标**：通过修改`device-daemon`源码，添加对自定义传感器数据的采集（如陀螺仪、加速度计）；
- **报告插件**：开发 CSV 解析脚本，自动生成趋势图（如用 Python 的 Matplotlib 绘制 FPS 波动曲线）。

### 3.3 企业级测试规范建议

1. **冒烟测试**：每次版本迭代前执行`wukong exec -T 30`，确保基础功能可用性；
2. **回归测试**：对修复模块执行`wukong special -C <包名> -r`录制回放，验证交互逻辑；
3. **压力测试**：每月一次全量采集`SP_daemon -N 0 -c -g -f -r`，结合 Monkey 测试模拟真实用户负载。
