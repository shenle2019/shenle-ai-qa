# 阶段十六. 鸿蒙OS专项测试命令行工具详解

## 一、SmartPerf Device性能工具使用指导

### 1.1 工具简介

**工具定位**：

- 基于鸿蒙系统开发的**实时性能功耗测试工具**，支持多指标量化监测与数据持久化分析，适用于应用开发阶段性能调优、整机功耗测试及版本迭代对比场景。

**核心能力**：

- **多维度指标采集**：覆盖FPS、CPU/GPU频率/负载、内存（RAM）、温度（TEMP）、网络流量等20+核心性能参数，每秒实时采样。
- **跨设备兼容性**：支持有屏/无屏设备，通过Device-daemon端shell命令行交互，适配API 9及以上系统版本。
- **可视化辅助分析**：支持每2秒自动截取应用界面截图（snapshot），辅助定位界面渲染异常。

**典型应用场景**：

- **游戏开发**：监测GPU负载（-g）与FPS（-f），优化图形渲染效率，解决画面卡顿问题。
- **视频应用**：分析CPU多核使用率（-c）与内存占用（-r），降低后台播放时的功耗与发热。

### 1.2 实现原理

**架构示意图**：

**关键流程**：

1. **参数配置**：通过Device-hap端设置采集项（如勾选FPS、内存）与采集策略（次数、时间段）。
2. **数据通信**：通过Socket协议将采集指令发送至Device-daemon端，支持实时数据传输与控制。
3. **指标采集**：Daemon端从设备节点（如/sys/devices）读取CPU/GPU频率、温度等原始数据，按秒级频率解析处理。
4. **结果输出**：生成CSV格式性能报告（默认路径：`/data/local/tmp/data.csv`），支持截图文件导出（`/data/local/tmp/capture/`）。

### 1.3 约束与限制

1. **系统依赖**：Device-daemon端需鸿蒙API 9及以上版本系统预置支持。
2. **硬件连接**：必须通过HDC（HarmonyOS Device Connector）连接物理设备，无法在模拟器中运行。
3. **环境配置**：

- 需提前安装HDC工具并配置环境变量，通过`hdc shell`进入设备终端。
- 执行测试前需确保设备已授权调试权限，且`hdc list targets`可识别设备SN号。

#### 1.4.3 CSV报告关键指标解读

|  |  |  |  |
| --- | --- | --- | --- |
| **指标** | **单位** | **理想值参考** | **异常分析** |
| `fps` | fps | ≥60 | 低于30fps时用户感知明显卡顿，需检查渲染逻辑或GPU负载 |
| `gpuLoad` | % | ＜70% | 持续高于80%可能存在图形资源过度占用，需优化Shader代码或纹理压缩 |
| `pss` | KB | 稳定无持续增长 | 内存持续上升可能存在对象泄漏，结合`heapAlloc`与`heapFree`分析内存分配 |
| `networkUp/networkDown` | byte/s | 符合业务场景预期 | 流量异常激增可能为后台服务请求频繁，需检查网络请求优化策略 |

## 二、wukong稳定性工具使用指导

### 2.1 功能架构与测试模式

**工具定位**：  
鸿蒙系统内置的**自动化稳定性测试工具**，通过模拟用户行为（点击、滑动、控件遍历）验证应用抗干扰能力，支持随机测试、专项测试、专注测试三种模式。

**模式对比**：

|  |  |  |  |
| --- | --- | --- | --- |
| **模式** | **核心功能** | **典型场景** | **参数特征** |
| 随机测试 | 随机注入事件（点击、应用切换、旋转屏幕） | 全功能路径覆盖，发现偶发崩溃 | `-a`（应用切换比例）、`-c`（次数） |
| 专项测试 | 按顺序遍历控件或录制回放操作 | 深度测试特定交互流程 | `-C`（控件遍历）、`-r`（录制） |
| 专注测试 | 高频操作指定类型控件（如按钮、输入框） | 核心控件压力测试 | `-f`（控件类型）、`-n`（单控件次数） |

### 2.2 核心命令与参数详解

#### 2.2.1 随机测试（`wukong exec`）

**参数配置逻辑**：

- **事件比例总和需≤100%**，超出时自动按比例压缩；
- **允许名单（**`-b`**）优先级高于禁止名单（**`-p`**）**。

|  |  |  |  |
| --- | --- | --- | --- |
| **参数** | **功能** | **默认值** | **业务场景示例** |
| `-b` | 设置允许测试的应用包名列表 | 无 | `-b com.tmall.wireless,com.taobao`：仅测试淘宝系应用 |
| `-a` | 应用切换事件比例（%） | 10% | `-a 25`：25%概率随机切换应用 |
| `-C` | 控件操作事件比例（%） | 70% | `-C 50`：50%概率点击/滑动界面控件 |
| `-T` | 测试总时间（分钟，与`-c`互斥） | 10分钟 | `-T 60`：持续测试1小时 |

**命令示例：电商应用随机稳定性测试**

- **录制回放**：`-r <文件>` 录制操作轨迹，`-R <文件>` 重复执行。

### 2.3 测试结果分析与定位

**输出路径与文件**：

- **最新版本路径**：`/data/local/tmp/wukong/report/YYYYMMDD_HHMMSS/`；
- **关键文件**：

- `wukong_report.csv`：统计崩溃次数、事件类型占比等；
- `wukong.log`：含操作日志与异常堆栈（通过`hdc file recv`导出分析）；
- `screenshots/`：控件操作截图（需启用`-I`或`-p`参数）。

**异常处理流程**：

1. **崩溃定位**：在`wukong.log`中搜索`AndroidRuntime`关键词，提取崩溃堆栈信息；
2. **界面异常**：对比`screenshots`目录下的截图，排查渲染错位或黑白屏问题（需启用`-B`参数监测）；
3. **性能关联**：结合SmartPerf的`data.csv`，分析测试期间的内存/CPU波动是否与稳定性问题相关。
