# shenle-api-cli 0.2 — 版本说明

> 给「看不太懂代码」的人写的导读。
> 0.2 修一个**真实场景下的卡死 bug**：shenle-test-runner 在 Windows 上跑 API 任务时，agent 调 shenle-api-cli extract 命令会陷入 bash 死循环。0.2 加 `call` 子命令把 send+extract 合并成一条命令，彻底避开 shell 兼容问题。

---

## 1. 这个工具有什么功能

### 0.2 新增：`call` 子命令

```bash
shenle-api-cli call req.json --field "$.data.token" --name "登录Token"
```

输出单行：
```
[OK] call: status=200 method=POST elapsed=110ms name=登录Token value=eyJhbGc... result_file=C:\...\shenle-api-results\xxx.json
```

效果 = `send` + `extract` 一步到位，**只需要一次 bash 调用**。

### 命令一览（0.2）

| 命令 | 干嘛的 | 推荐度 |
|------|--------|--------|
| `call <req.json> --field ...` | **0.2 推荐**：send + extract 一步到位 | ⭐⭐⭐ |
| `send <req.json>` | 只发请求，落盘 result | ⭐⭐ |
| `extract <result.json> --field ...` | 从 result 文件抽字段 | ⭐（需先 send） |
| `assert <result.json> "..."` | 自然语言断言 | ⭐（特殊场景） |

## 2. 修的 bug（0.2）

### Bug 现象

shenle-test-runner 跑 API 测试时，agent 调完 `shenle-api-cli send req.json` 拿到 result_file，然后想调 `extract` 抽 token，**陷入死循环**，最终跑不完。

实际日志（用户的真实跑测）：
```
[OK] send: 200 POST http://... elapsed=110ms result_file=...
Command failed: result_file="C:\Users\..."    ← agent 试 bash 赋值
Command failed: result_file='C:/Users/...'    ← 换单引号
Command failed: shenle-api-cli extract "C:/Users/..."  ← 直接调
ls: cannot access '\C:/Users/...'              ← 改 ls 找文件
20260924-...json 20260924-...json ...          ← ls 通了
...                                           ← 然后 agent 又卡住
```

测试在 Flow 2 task 3（正常登录）卡了 7+ 分钟没进展。

### 根因（Windows 专属）

agentscope 的内置 Bash 工具在 Windows 上**强制走 `cmd /c`**（[代码](D:/Code/AIQECourse/Phase1/.venv/Lib/site-packages/agentscope/tool/_builtin/_bash.py#L709-L712)）：

```python
if self._backend.os_name == "nt":
    shell_command = ["cmd", "/c", command]
else:
    shell_command = ["/bin/sh", "-c", command]
```

而 0.1 的 SKILL.md 教 agent 用**纯 bash 语法**：

```bash
result_file=$(shenle-api-cli send req.json | grep -oP 'result_file=\K\S+')
token=$(shenle-api-cli extract "$result_file" --field "$.data.token" | grep -oP 'value=\K.*')
```

这玩意在 Windows cmd.exe 里**全是错的**：

| bash 写法 | cmd.exe 行为 | 结果 |
|----------|------------|------|
| `result_file="value"` | cmd 试图执行命令 `result_file="value"` | 不是内部命令 |
| `result_file='value'` | cmd 里 `'` 不是引号字符 | syntax error |
| `$(...)` | cmd 不支持 | syntax error |
| `grep -oP` | cmd 没有 grep | 不是内部命令 |

agent 每次 `Command failed:` 都被提示失败，陷入"换个写法重试"的死循环。

### 0.2 修法：加 `call` 子命令

**核心思路**：把 send + extract 合并成一个命令，agent 只需要发**一次** bash 调用，不涉及管道、变量赋值、引号兼容。

```bash
# 0.2 推荐
shenle-api-cli call req.json --field "$.data.token"

# vs 0.1（Windows 上会死循环）
result_file=$(shenle-api-cli send req.json | grep -oP 'result_file=\K\S+')
token=$(shenle-api-cli extract "$result_file" --field "$.data.token" | grep -oP 'value=\K.*')
```

`call` 在 Windows / Linux / Mac 三平台**完全一致**（就是单条命令，不碰 shell）。

## 3. 0.2 关键变化 vs 0.1

### 用户视角

| 维度 | 0.1 | 0.2 |
|------|-----|-----|
| API 任务调用方式 | send → extract（两命令 + 管道/赋值） | **call（一命令搞定）** |
| Windows 兼容 | ❌ 死循环 | ✅ 单条命令 |
| Linux/Mac | ✅ bash 语法 | ✅ call 一样能用 |
| 输出格式 | send 输出 `[OK] send: ...`、extract 输出 `[OK] extract: ...`（两行） | call 单行 `[OK] call: status=... name=... value=...` |
| result_file | 仍落盘（call 内部调 send + save_result） | 同左 |

### 代码视角

| 文件 | 改动 |
|------|------|
| `commands.py` | 加 `cmd_call`（~70 行）+ `_do_extract` 内部辅助（共享 JSONPath / NL 分支） |
| `cli.py` | 加 `call` 子命令的 argparse + 注册到 `_HANDLERS` |
| `__init__.py` | 版本号 0.1.0 → 0.2.0；docstring 加 0.2 新增说明 |
| `pyproject.toml` | 版本号 + description 强调 `call` 跨平台兼容 |
| `skill/shenle-api-cli/SKILL.md` | 重写"调用模式"章节：call 放第一个；加"Windows 走 cmd.exe"警告；删除会死循环的 bash 写法 |

### 0.1 → 0.2 兼容

- `send` / `extract` / `assert` 命令**完全不变**
- `call` 是**新增**，不是替代；旧的 send+extract 用法在 Linux/Mac 上仍能用
- 输出格式 `[OK] send: ...` / `[OK] extract: ...` 仍兼容 0.1 的下游解析

## 4. 跟 shenle-test-runner 怎么配合

shenle-test-runner 跑 API 任务时：

```
runner 渲染 task.input → 给 agent UserMsg（detail 已渲染）
agent 思考 → 调 shenle-api-cli tools
  ├─ 0.1：send → extract（Windows 上死循环）
  └─ 0.2：call（一次搞定）✅
agent 输出 [OK] task=xxx 或 [FAIL] task=xxx reason=...
runner 用 task.output 的 regex 从 agent stdout 抽变量写回 flow.context
```

0.2 + shenle-test-runner 6.3 配合后，Windows 上 API 测试**应该**能稳定跑完，不再卡死。

---

## 5. 一句话总结

> 0.2 = send + extract 合并成 `call` 一条命令，**Windows / Linux / Mac 三平台一致**，彻底避开 cmd.exe / bash 跨平台 shell 兼容问题。
> 用户视角：API 任务"一次调用"搞定；agent 不再死循环。
