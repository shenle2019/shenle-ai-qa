# 第 25 章 · 元素定位与窗口树

界面上每个控件都有属性：文字、id、类型、坐标。定位就是「用哪几个属性把唯一一个控件挑出来」。

## 1. 窗口树长什么样

`adb shell uiautomator dump /sdcard/w.xml` 会输出当前界面的一棵树：根节点是 `FrameLayout`，下面按层级挂 `TextView`、`Button`、`EditText`、`RecyclerView`。

每个节点带这些关键属性：

| 属性 | 用途 | 注意 |
| --- | --- | --- |
| `text` | 可见文字 | 文案会改，密码框显示成掩码 |
| `resource-id` | 开发给的稳定标识 | 最有价值，但第三方 App 可能为空 |
| `content-desc` | 无障碍描述 | 图标按钮通常只有它 |
| `class` | 控件类型 | 常用来兜底或做数量断言 |
| `bounds` | `[x1,y1][x2,y2]` | 点击坐标取中心点 |
| `clickable` | 是否可点 | 文字节点常常不可点，要点它的父节点 |

## 2. 定位优先级

1. `resource-id`：最稳。开发改布局时通常不会动它。
2. `content-desc`：图标按钮首选。
3. 文字：可读性好，但最容易随文案变。
4. 类型 + 下标：能跑通，但界面一改顺序就错。
5. 绝对坐标：只在「反正就这一个按钮」时用，且要按分辨率换算比例。

## 3. 歧义比找不到更麻烦

`find()` 找不到会抛 `LookupError`；匹配到多个也抛，并列出前几个候选。这一条是刻意设计的：自动化里最危险的是「顺手点了第一个」，它不会报错，只会在某天悄悄点错。

## 4. 等界面出现，而不是 sleep

固定 `sleep(3)` 在快设备上浪费时间，在慢设备上直接失败。`wait_for()` 轮询窗口树，直到条件成立或超时；超时的时候把当前界面的前几个文字节点带进异常，一眼能看出卡在哪。

## 常见坑

1. **dump 拿到的是上一个界面**：动画没结束就 dump 了，套一层 `wait_for` 再取树。
2. **`text` 里带空格导致匹配失败**：用 `text_contains`，别硬拼全串。
3. **WebView / 游戏引擎界面 dump 不到内容**：整块只有一个 `SurfaceView`，只能走坐标或图像识别。
4. **中文匹配不上**：XML 是 UTF-8，但终端显示是 GBK，看到的乱码不代表数据错。

## 自测

1. 为什么「找到多个」要报错而不是返回第一个？
2. `bounds` 是 `[0,240][1080,420]`，中心点坐标是多少？
3. `clickable=false` 的文字节点，想点它应该怎么办？
4. `wait_for` 超时后，异常里为什么要带当前界面的文字？

## 附：自测答案

1. 返回第一个会让「点错控件」变成静默故障；报错并列出候选，才能在上游修定位。
2. `(540, 330)`：`(0+1080)/2` 与 `(240+420)/2`。
3. 往上找最近的 `clickable=true` 祖先（`clickable_ancestor()`），用它的中心点。
4. 让失败自带上下文：看到「当前界面：登录 / 用户名 / 密码」就知道是停在登录页，而不是 App 崩了。

## 学生常问

**Q：为什么不直接按坐标点？**

A：坐标和分辨率、系统栏高度、字体缩放都相关，换台设备就偏。定位是「按语义找」，坐标只是最后一步的落点。

**Q：第三方 App 没有 resource-id 怎么办？**

A：退到 `content-desc` 或文字；再不行用「类型 + 相对位置」（比如第二个 `EditText`）。这类 App 的自动化本身就更脆，要在报告里标出来。

**Q：一个页面要不要缓存窗口树？**

A：同一次操作里可以复用一帧；跨操作必须重新 dump，否则点击后界面已变，旧树会误导。

## 面试题

**Q：元素定位不稳定，你会从哪几个方向改？**

A：优先换更稳的属性（id/desc）；给关键控件加上下文条件（在某个容器内查找）；把「等界面」补上；最后才是加兜底定位。

**Q：怎么判断一个定位是「真的稳」？**

A：看它在多台设备、多次冷启动、不同系统版本下是否都能命中；只在自己机器上跑通不算。

**Q：uiautomator 和 Appium 的定位有什么差别？**

A：同源。Appium 的 `find_element` 底层也是 uiautomator 的 dump 结构，差别在于它多了跨平台抽象与等待策略。

## 延伸知识

- `adb shell uiautomator dump --compressed`：压缩空节点，树更小更快。
- `dumpsys activity top` 能看到当前 Activity 的 View 层级，比 dump 更细。
- `bounds` 可以判断「是否在屏幕内」，滚动查找时很有用。
- 同一个 `text` 出现多次时，用「父容器 id + text」组合定位最稳。
