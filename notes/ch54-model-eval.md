# 第 54 章 · 大模型评估与部署测试

模型评估测的是「能力边界在哪」，部署测试测的是「这份能力在真实流量下还剩多少」——两件事都不能由应用回归测试代替。

## 1. 为什么评估要单独做

| 维度 | 应用测试 | 模型评估 |
| --- | --- | --- |
| 对象 | 一条功能链路 | 模型在一类任务上的能力 |
| 问题 | 这个接口通不通 | 这个模型够不够用、比上一个强还是弱 |
| 断言 | 状态码、字段、文案 | 指标 + 分群 + 数据集版本 |
| 失败形态 | 报错、超时 | 分数缓降、某一群体明显更差 |

模型换版本，应用代码一行没改，回归可以全绿，效果却掉十个点。题目 124 给了四个理由：模型能力是应用效果的上限、评估是选型依据、评估指出优化方向、两者测试对象与目标不同。评估至少要有三件产出，缺一件结论就不可比：基线分数、分群短板（哪类输入最差）、评测集版本号；没有版本号的分数，下周再跑一次就不知道变化来自模型还是数据。

## 2. 评测数据集与 garbage in

题目 126 把数据质量拆成五性：准确、完整、一致、时效、多样；题目 127 补了数据集本身的五个要求：任务覆盖（核心 + 边界）、难度梯度（简单/中/难）、领域多样、语言风格多样、评分标准客观可重复。

四个能直接判定的反例：

- 只收「退款」不收「部分退款/跨境退款」→ 覆盖缺失，模型在边界上错，总分还很高。
- 两个标注员对「7 天」是否含头一天理解不同 → 一致性差，同一答案两次评分不同。
- 全是书面语 → 口语输入一进来就崩。
- 评测集混进训练数据 → 训练集与测试集重叠属于数据泄露（题目 161），分数不再代表泛化能力。

最小字段：样本 id、输入、参考答案、评分规则、来源。数据集打版本号（`eval-v3` 这种），换一版必须重跑基线，否则「涨了 2 分」可能只是换了题。

## 3. 分类指标：准召 F1 手算

```python
GOLD = [("good", "good"), ("good", "bad"), ("bad", "bad"), ("good", "good"), ("bad", "good")]
```

以 `good` 为正类逐条数：第 1、4 条是 TP，第 2 条是 FN，第 3 条是 TN，第 5 条是 FP。所以 `TP=2`、`FN=1`、`FP=1`、`TN=1`：

- 精确率 `P = 2/(2+1) = 0.6667`：判为 good 的 3 条里，2 条真是 good。
- 召回率 `R = 2/(2+1) = 0.6667`：真 good 的 3 条里，捞回 2 条。
- `F1 = 2PR/(P+R) = 0.6667`。
- 准确率 `acc = 3/5 = 0.6`。

`acc` 和 `F1` 不相等，因为 `acc` 把 `TN` 算进分子，`F1` 完全不看 `TN`。类别不平衡时这个差别会要命：100 条里 95 条 bad，全判 bad 也有 `acc=0.95`，但 `recall=0`，要拦的风险单一条没拦。选指标看代价：漏判代价高（风险拦截、违规内容）看召回；误判代价高（自动退款审批、自动封号）看精确率；两者都要就给 F1，或按业务定权重的 F-beta。

实现上有个细节：分母为 0 时返回 `0.0` 而不是抛异常（`labs/_shared/eval_sim.py:23-28`）。测试要专门覆盖「全预测为负」这种退化输入，否则线上真出现时指标代码先崩。

## 4. 生成指标：BLEU/ROUGE 的局限

```
参考：退款需要在签收后七天内申请并附上订单号
好答案：退款需要在签收后七天内申请
短答案：退款
```

实测：好答案 BLEU-like 1.0、ROUGE-L-like 0.6842；短答案 BLEU-like 1.0、ROUGE-L-like 0.1053。两个数说的是同一件事的两面：

- `bleu_like` 只算 n-gram 精确率，**没有 brevity penalty**（`eval_sim.py:43-55`）。「退款」两个字的 bigram 全中，拿满分 1.0，和完整答案打平；丢掉「七天内」「附订单号」这些关键约束，BLEU 一点没扣。
- `rouge_l_like` 是最长公共子序列除以参考长度，短答案必然低：`2/19 = 0.1053`。它惩罚短，BLEU 奖励短，两个指标方向相反。

题目 134 的局限清单可以直接背：BLEU 惩罚长句、忽略语义、依赖参考答案；ROUGE 偏向长句；共同点是测不了流畅性、创新性、事实正确性。所以生成任务要三层：自动指标（快速发现「变差了」）+ 任务指标（退款场景断言「包含金额、时限、单号」）+ 人工抽检（事实对不对）。自动指标只用来做版本间回归，不用来证明「够好了」。短答案虚高最坏的结果不是分数错，是模型学会了「少说少错」：回答越来越短，指标越来越好看，用户越来越看不懂。

## 5. 偏置探针与公平性

探针是四条文本、两个分组，每组各一条「熟练」一条「会写」：

```python
texts = ["他熟练使用 pytest", "她熟练使用 pytest", "他会写接口测试", "她会写接口测试"]
labels = ["male", "female", "male", "female"]
```

有偏打分器给「熟练」8 分、「会写」5 分，出现「她」再减 2 分；公平打分器不减。实测有偏 male 6.5 / female 4.5 / gap 2.0，公平 male 6.5 / female 6.5 / gap 0.0。male 是 `(8+5)/2=6.5`，female 是 `(6+3)/2=4.5`；gap 的 2.0 只能来自「她」，因为两组的能力词构成完全一样。这就是探针的设计要点：**同一能力，只换敏感属性**。

常见的探针错误是能力没配平：一组全是「熟练」，另一组全是「会写」，female 均值被能力构成拉低，gap 里混进了能力差，结论就废了。gap 也没有通用安全线：招聘、信贷这类场景按 0 容忍设计；客服语气这类可以容忍小差异，但要记录方向（是稳定偏低还是随机波动）。经验判断，未验证：gap 的绝对值不如「同一探针跨版本是否变大」有用，前提是探针本身不变。题目 129 列了四类偏置（性别、地域、行业、种族文化），题目 130 给了五种测法（敏感属性替换、偏见词汇分析、分群指标、特定场景、对抗测试），本章的替换法就是第一种的最小实现。

## 6. 数据漂移、概念漂移与时效

PSI 的算法是分箱后逐箱算 `(a-e) * ln(a/e)` 再求和（`eval_sim.py:101-119`），分级写在注释里：`<0.1` 稳定、`0.1–0.25` 需关注、`>0.25` 显著漂移。实测同一分布 `PSI=0.0`（每箱 `e==a`，`ln(1)=0`），整体右移 3 之后 `PSI=18.2943`。

18.29 这个数要谨慎解读：分箱边界由两组的合并 `min/max` 决定，整体平移会让几乎所有样本换箱，所以 PSI 对平移极敏感。它适合发现「整体换了分布」，不适合单独判断影响大小；PSI 只当报警器，不当结论。题目 131 区分了两种漂移：数据漂移是输入分布变，概念漂移是标签含义变，PSI 只测前者。标签含义变了（比如「价保」从 7 天改成 15 天），PSI 可以是 0，模型却已经全错，这类只能靠人工抽检和业务指标发现。

时效（题目 132）是另一类「知识过期」：知识截止日期之后的事件，正确行为是说「不知道」，不是编。用例要卡时间边界——截止日前的事件、截止日后的事件各一条，断言的是「是否承认不知道」，不是「知不知道某个事实」。漂移监控的最小配置：固定基线分布 + 每日整体 PSI + 分群 PSI（新用户/老用户分开算）；只看整体，会把一个小群的剧烈漂移平均掉。

## 7. 鲁棒性与异常输入

六类输入逐个喂一遍（`labs/ch54-model-eval/ch54_cases.py:38-45`）：空串、20 个空格、`退款` 重复 500 次、纯 emoji、控制字符 `\x00\x01`、`'; DROP TABLE orders; --`，实测六条全是 `ok`。

「ok」的定义要读清楚：桩函数是 `lambda t: t or "空输入"`，只要不抛异常、返回非 `None` 就记 `ok`。这只证明「没崩」，不证明「答得对」。真实模型要加三条断言：不崩、有合理兜底话术、不泄露系统提示也不执行注入。题目 147 的六类异常输入（空、超长、特殊字符、乱码、多语言混合、注入）与本例一一对应；题目 148 再补情感极端、伦理困境、敏感话题。超长输入要测两个边界：刚好占满上下文、超出 1 个 token；前者容易在拼上系统提示后溢出，后者要看是截断、报错，还是悄悄丢前半段。题目 149 给了健壮性的六个维度：错误率、鲁棒性得分、安全性得分、恢复能力、一致性、人工评估；最常漏的是「一致性」——同一语义换三种说法，结论应该一致，三种说法三种答案说明模型在抓措辞而不是抓意思。

## 8. 三种部署、可用性、版本与监控

| 方式 | 优势 | 劣势 | 测试重点 |
| --- | --- | --- | --- |
| 本地 | 数据可控、延迟低 | 初始投入大、扩展受限 | GPU/显存兼容、冷启动、长时间稳定性 |
| 云端 | 弹性、按需付费 | 网络延迟不可控、依赖云服务 | 网络抖动、依赖故障、成本失控 |
| 边缘 | 延迟极低、省带宽、隐私好 | 算力/内存/能耗受限、管理复杂 | 模型压缩后的精度损失、冷启动、实时性 |

三种方式的差异见题目 140–143。同一个模型换一种部署，测试集要换：本地测显存和并发，云端测网络与降级，边缘测算力与压缩损失。

可用性看两个数。成功率：`success_rate([True]*18 + [False]*2) = 0.9`。P95：`p95([120,130,135,140,150,200,900]) = 900`——7 个样本，`ceil(0.95*7)-1 = 6`，取到最后一个，P95 就是最大值；`p95([1..10]) = 10` 用的是最近秩，不做插值（`eval_sim.py:130-135`）。样本量决定分辨率：7 个样本的 P95 没有分辨力（第 32 章：100 个样本都算不出可信 P99）。经验判断，未验证：P95 至少 200 个请求，且要剔除预热。

成本按 token 算：`tokens_cost(3200, 800) = 0.0128` 元（输入 0.002/千 token、输出 0.008/千 token，示例价，不是任何厂商报价）。一次对话 1.28 分，10 万次 1280 元；注意要按「每成功任务」算，不是「每次调用」——重试三次才成功，单次成本要乘 3。版本管理（题目 150）：命名（模型名\_版本\_日期）、元数据（训练数据/参数/评估结果）、可回滚、A/B、模型仓库、灰度、合规；测试要断言「回滚后指标回到基线」，不是「回滚命令执行成功」。监控（题目 152）：性能看 P50/P95/P99、吞吐、资源；质量看成功率、错误类型分布、输出抽检；业务看满意度、任务完成率；安全看拦截率。上线首日最容易漏的是冷启动与显存泄漏（题目 151），前者会让首屏 P95 虚高，后者要跑够时长才看得出来。

## 附：自测答案

1. `TP=2`（第 1、4 条）、`FN=1`（第 2 条）、`FP=1`（第 5 条）、`TN=1`（第 3 条）；`P=2/3=0.6667`、`R=2/3=0.6667`、`F1=0.6667`、`acc=3/5=0.6`。
2. BLEU 只算 n-gram 精确率且没有长度惩罚，「退款」的所有 bigram 都在参考里，所以满分；ROUGE-L 除以参考长度，短答案分子小。BLEU 的方向更危险，它会把「少答」奖励成正确答案。
3. 不能。探针只能证明「在这四条上、这个打分器差 2 分」。要下结论需要更多样本、配平能力、覆盖更多场景；而且「没有测到偏置」不等于「没有偏置」。
4. 每个箱的期望占比和实际占比相等，`ln(a/e)=ln(1)=0`，求和为 0。右移 3 让所有样本都换了箱，每箱的 `a/e` 偏离极大，求和放大到 18.29；这是分箱边界随两组合并 `min/max` 变化导致的敏感性。
5. 不能。7 个样本的 P95 就是最大值，900ms 可能只是一次冷启动。要预热、要至少 200 个样本、要区分 P95 与 P99，才谈得上 SLA。

## 学生常问

**Q：评测集要多大才够？**

A：不看总数看分群。主任务每类至少 100 条，才能在 95% 附近谈置信区间（n=100 时约 ±6 个百分点）；长尾和高风险场景每类 30 条，只用来发现「有没有错」，不用来报精确分数。50 条时 0.90 的 95% 区间约 ±8 个百分点（按二项分布估算），0.90 和 0.92 分不出高下。

**Q：BLEU 低就说明模型差吗？**

A：不一定。换个同义说法 BLEU 就掉，但语义没错。先用任务指标（关键字段是否齐全）判断对错，BLEU 只用于同版本之间的回归对比。

**Q：偏置探针要多少条？**

A：每组至少 20 条，且能力构成要配平。4 条只能做演示，不能下结论；配平比数量更重要，一组全「熟练」一组全「会写」，条数再多 gap 也是假的。

## 面试题

**Q：模型评估和应用测试的区别是什么？**

A：对象（能力边界 vs 功能链路）、断言（指标+分群 vs 状态码/字段）、可复现性（数据集版本+温度/种子 vs 代码版本）、失败形态（分数缓降 vs 直接报错）。模型换版本不改一行应用代码，回归能全绿而效果掉点，这就是要单独做评估的原因。

**Q：给你一个客服模型，怎么设计评测？**

A：先分任务（问答、退款、投诉、闲聊），每类建集并补边界与对抗样本；再定指标（分类用 P/R/F1，生成用任务字段+人工）；然后定基线（现网版本+候选模型）；最后分群看短板（新老用户、地区、渠道）。上线后用 PSI 加抽检做持续评估。

**Q：accuracy 很高为什么还可能不可用？**

A：类别不平衡。95% 负样本时全判负也有 `acc=0.95`，但 `recall=0`，要拦的风险单一条没拦。要看混淆矩阵和分群召回，不能只看总分。

**Q：上线后指标掉了，怎么定位？**

A：先分「输入变了」还是「模型变了」：比 PSI、比版本、比分群。输入没变、版本没变、单群掉，查该群样本和上游数据；三者都变，先回滚再分析（题目 153 的止血顺序：识别→止血→分析→修复→复盘）。

## 延伸知识

- 指标要按任务选，不是所有生成任务都看 BLEU：题目 135 给的映射是 QA 用 EM/F1/MRR、摘要用 ROUGE-L/METEOR、开放生成用困惑度加人工。本章只实现了分类指标与 BLEU/ROUGE，EM、MRR、METEOR 未覆盖。
- 公开榜单替代不了业务集：题目 128 里 MMLU 覆盖 57 个学科、C-Eval 覆盖 52 个中文领域，粒度是「学科」；业务要的是「退款话术是否合规」，两者不是一回事。榜单分数只用于筛候选模型。
- PSI 测不到概念漂移：题目 131 明确区分输入分布变化与标签含义变化，而 `psi()` 只吃两组数值（`eval_sim.py:101-119`），标签含义变了它仍然是 0。这类漂移要靠人工抽检和业务指标发现。
- 部署测试最容易漏的是冷启动：题目 151 把「首次调用延迟高、应预热后再测」列在第一条；本章 `p95()` 不剔除预热请求，7 个样本里 900ms 那条如果是冷启动，P95 就被它单独决定（`eval_sim.py:130-135`）。真实报告要标注是否含预热。
