第 21 章 · 视觉回归与可访问性 ​

本章目标：让「样式被改了」和「键盘用户用不了」这两类问题能被自动发现。做完你能说清像素比对为什么必须带阈值。

1. 视觉回归在测什么 ​

它不测「好不好看」，测的是**「和上一版比有没有意外变化」**。

python
def diff_ratio(baseline, current, tolerance=16):
    left, right = Image.open(baseline).convert("RGB"), Image.open(current).convert("RGB")
    if left.size != right.size:
        raise ValueError(f"尺寸不一致：{left.size} vs {right.size}")
    diff = ImageChops.difference(left, right).convert("L")
    mask = diff.point(lambda v: 255 if v > tolerance else 0)
    return round(sum(1 for v in mask.getdata() if v) / (left.size[0] * left.size[1]), 6)

三个设计点：

设计为什么
只比同尺寸尺寸不同比出来是 100%，没有信息量，直接报错
单像素容差 16/255压掉抗锯齿、字体渲染抖动，否则同一页面两次截图也会「不一致」
输出比例而不是布尔「差 0.03%」和「差 40%」是完全不同的结论

阈值经验：0.2% 以内算通过；整页重构时先更新基线，再让人 review 截图 diff。

2. 基线怎么管 ​

  • 基线进 Git（baseline/），和代码一起 review；
  • 更新基线要单独一次提交，信息写清「为什么变」（改字体/改布局/修 bug）；
  • 基线数量别贪多：首页 + 关键流程页 + 一个空态，5–10 张够了。

5. 什么时候不该用视觉回归 ​

  • 内容频繁变的区域（时间戳、推荐位、随机文案）——要么遮罩，要么别截这块；
  • 动画过渡中截图——每次都是不同帧；
  • 跨操作系统字体渲染——同一页面在 Win/Mac 上像素本来就不同，基线要按平台分目录。

6. 自测 ​

  1. 为什么像素比对一定要容差？
  2. 差异 0.05% 和 5% 分别意味着什么？
  3. duplicate-id 为什么算可访问性问题？
  4. 视觉基线多久更新一次？

附：自测答案 ​

  1. 因为渲染不是确定性的：抗锯齿、字体 hinting、GPU 合成都会让同一页面两次截图有几个像素不同。没容差会把「噪声」当「回归」，用例变成噪声源。
  2. 0.05% 通常是局部元素位移或文案微调，值得看一眼但不一定阻断；5% 基本是布局变了或整块没渲染，要阻断并人工确认。
  3. <label for="x"> 只能命中第一个 id="x"。id 重复会让「点标签聚焦输入框」失效，读屏也会念错控件。
  4. 不按时间，按变更：只有「有意改样式」时才更新，并且和改样式的代码同一次提交。定期无脑更新会把真实回归一起洗掉。

学生常问 ​

Q：视觉回归和人工 UI 走查冲突吗？

A：不冲突，互补。视觉回归只能回答「有没有变」，「变得对不对」还得人看。它的价值是把「每天扫 20 页」压缩成「只扫有 diff 的 3 页」。

Q：a11y 检查要不要上 axe-core？

A：先跑通这五条内置规则，能覆盖最常见的问题；需要更细（对比度、ARIA 组合）再引 axe，避免一上来被几百条告警淹掉。

Q：截图存哪？进 Git 吗？

A：基线进 Git（小、需要 review）；每次运行的截图存 artifacts/，不进 Git，只在失败时作为附件上传到 CI。

面试题 ​

Q：你们有做视觉回归吗？怎么控制误报？

A：做了，三个手段：单像素容差（16/255）、区域遮罩（时间戳、随机推荐）、阈值分级（0.2% 内忽略，0.2%–2% 警告，>2% 阻断）。不控制误报的视觉回归，两周就会被团队关掉。

Q：Web 可访问性你们测哪些？

A：最小集合是图片 alt、表单可访问名、控件可读文本、标题层级、id 唯一；再往上是键盘可达（Tab 顺序、焦点可见）、对比度（4.5:1）、ARIA 语义正确。前五条能自动查，后三条需要工具 + 人工。

Q：UI 测试的稳定性你一般怎么提升？

A：定位用 testid、等待用 expect 而非 sleep、状态用夹具隔离、失败留证据（截图 + trace）、把环境依赖降到最低（本章的迷你站就是本地起、无外网）。

Q：怎么判断一个 UI 用例该删？

A：三个信号：半年没失败过且覆盖的是静态内容、失败总是环境原因、维护成本超过它拦住的问题。删之前先看它守的是什么风险，别把「唯一守着支付流程」的用例删了。

延伸知识 ​

  • ImageChops.difference 的替代：pixelmatch 能做抗锯齿感知的比对，代价是要 Node 或额外依赖；纯 Python 场景用当前方案够用。
  • 遮罩（mask）：Playwright 截图支持 mask=[locator]，把动态区域涂成粉色再比对，比事后裁图省事。
  • 可访问性也是可测的接口：get_by_role 能用，说明页面语义没坏；「role 定位不到」往往就是 a11y 问题。
  • 对比度速算：正文 4.5:1、大字 3:1 是 WCAG AA 的线；把品牌色算一遍，很多「看起来还行」的灰字其实不达标。
