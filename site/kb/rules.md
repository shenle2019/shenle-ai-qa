# 内容更新规则

这份规则是给「以后每一次更新」用的：写新章、补旧章、改站点，都按这里来。

## 三条硬规则

1. **知识要扩充，不是抄录。** 每章除了主线知识，还要补相关延伸内容：能并入正文的并入正文，量太大就单开一页（放 `/kb/`），并在章节页给出入口。补充内容用自己的话重写，保留可执行的细节，删掉口号。
2. **所有问题都必须带答案。** 自测题、学生常问、面试题，写完问题紧接着写答案，不允许只留问题。答案要能直接判断对错、能落到代码或命令上。
3. **术语统一。** `章节` 一律叫 **测试全栈知识库**，`实验` 一律叫 **实操记录**。正文里说「本章实操」「实操目录」。

## 每一章的结构

```
## 1. …              主线知识，每节带可运行代码
## N. 本章实操        指向 labs/chXX-*，给运行命令
## 附：自测答案       先列问题（保持编号），再逐条给答案
## 学生常问           Q/A，3–4 条
## 面试题             Q/A，3–4 条
## 延伸知识           4 条要点
```

顺序固定，`## 附：自测答案` 这个标记用来判断该章是否已补完，不要改名。

## 写作口径

- 先结论后原因：一句话说清该怎么做，再解释为什么。
- 能给数字就给数字：超时几秒、重试几次、截断多少字符、并发几个。
- 反面例子要写：错误写法 + 为什么错 + 正确写法，三段以内。
- 不写来源：不出现课程名、机构名、课件、老师、文档出处。
- 不写空话：「非常重要」「一定要重视」删掉，改成具体后果。

## 更新流程

1. 改 `notes/chXX-*.md`（笔记是唯一内容源，站点用 `<!--@include-->` 引用，不重复维护）。
2. 需要新页面时：`site/kb/<主题>.md`，并在 `config.mts` 侧栏挂上。
3. 跑测试：`.\.venv\Scripts\python.exe -m pytest labs -q`，必须全绿。
4. 本地构建：`cd site; npm run build`，确认 `build complete`。
5. 截图留证：`python scripts/shot_site.py`、`python scripts/shot_live.py`。
6. 提交推送：`git add -A; git commit -m "<type>: <一句话>"; git push origin HEAD`。
7. 等 Actions `success`，再打开线上页面确认内容已更新。

## 新增一章的清单

- [ ] `notes/chXX-<slug>.md`：六段结构写全
- [ ] `labs/chXX-<slug>/`：一个能跑的 demo + 一个 pytest 文件
- [ ] `site/chapters/chXX.md`：frontmatter + `<!--@include-->`
- [ ] `config.mts` 侧栏、`index.md` 进度表、`chapters/index.md`、`labs/index.md`、`README.md` 各加一行
- [ ] 跑 `pytest labs -q`，文档里的数字与实际一致

## 质量红线

- 文档里的命令必须真跑通，贴的输出必须是真实输出。
- 断言必须可判定：写状态码、字段、值或格式，禁止「功能正常」。
- 数字（测试条数、章节数、耗时）以实际运行结果为准，改完回头核对首页与索引页。
